# AI 程序模块实现

## 职责与入口

负责本次功能的代码、必要接入和事实验证。进入 UE 项目时，先按 `ue-project-context` 读取项目入口，再读取 `ai-native-programming` 和本 Skill。共用的编码、配置和验证约束以 `ai-native-programming` 为准。

从总控取得需求、允许修改范围和架构交接。实现 Agent 聚焦落点，架构 Agent 负责相关上下游的结构分析；实现中仍需核对代码事实，不把交接当成无需验证的结论。

## 读取与开工

按总控提供的确定路径读取已落盘的架构交接文档，以及与本次行为相关的策划需求、指定源码和配置/资产入口、直接依赖的上游交付；不只依赖聊天转述。已有架构基线或共享业务约定时，只读适用部分；不存在时不为开工补建一套基线。

先确认入口、复用接口、修改落点和验证方式。清楚后开始实现，无需先提交架构符合性表或逐项内容分类表。局部事实缺失时可以沿调用和数据依赖补读，避免全仓库扫描。若需要改变需求、公共约定或职责归属，回交相应问题；其他已明确部分继续推进。

## 实现

- 沿用现有请求、运行结果和事件接口，避免复制已有机制或另起一套运行路径。
- 按职责安排运行逻辑、内容定义、表现和测试适配；不把具体样例规则写入通用生命周期，也不把无关功能堆进 Character、Controller 或一个大文件。
- 优先修改合适的既有边界；确有独立职责再新增组件或文件，不为形式上的分层增加空壳。
- 完成当前行为需要的能力，不顺带增加未被需求使用的通用框架、配置工具或可靠性设施。
- 架构交接已经覆盖的接口接入可以直接实现；超出约定的公共接口变化、跨模块职责调整和未定义体验选择交回总控。普通编译、类型、include 和局部连接问题自行修复。

内容可以使用已有配置/结构化资产，必要时使用独立的类型化 C++ 定义提供器。说明当前内容来源和调用边界即可；不为“以后可能换载体”提前建设迁移工具。测试样例也要沿公共接口运行，暂时实现的范围和限制据实说明。

## 验证

执行能判断本次行为和直接影响的编译、局部检查、运行或 PIE 验证，优先复用现有入口。涉及配置和职责分离时，核对内容来源、调用关系和有代表性的实际调用点。新增工具应解决明确的验证缺口，不能先把完整采样或验收平台当作功能前置任务。

记录复现入口、结果摘要和必要证据位置；未运行的部分明确标注，不用静态检查代替运行结论，也不长期复制完整日志。

## 交付

简明说明完成的行为和需求对应关系、修改文件、接口或职责变化、验证结果、未完成或未验证部分，以及需要下游知道的限制。只记录影响交接的假设和偏离，不为每项局部修复生成新文档。

交付可由总控保存在可检索的上下文包；需要跨对话长期复用时，更新任务现有交接文档。项目已有 `Docs/ProgramWorkflow/<TaskName>/Batches/<BatchName>/Implementation/` 时可沿用，无需为了符合目录格式新建整套结构。

若改变模块职责、运行入口、配置/资产入口或功能映射，指出需要同步的项目代码文档；Review 核对后按 `project-documentation` 更新最小必要事实。局部实现细节未影响地图时不扩写文档。修复继续在原任务上下文中完成，交付事实供独立 Review 判断。
