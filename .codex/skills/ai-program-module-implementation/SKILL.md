# AI 程序模块实现

## 入口关系

本 Skill 由程序工作流总控通过独立本地任务对话调用。进入 UE 项目时，先完成 `ue-project-context` 的项目文档路由，再读取 `ai-native-programming`，最后读取本 Skill。实现对话只处理总控交给的边界明确模块，不自行扫描或规划整个项目。

## 目标

在已有架构基线和模块约定下，实现一个边界明确的 UE 模块或纵向功能切片，并留下可被总控、Review 和后续模块读取的实现摘要。

## 项目路径和交接

默认使用以下相对仓库路径：

- 领域规格：`<UEProjectRoot>/Docs/Planning/<TaskName>/` 中与当前模块对应的文档；
- 当前共享功能基线：`<UEProjectRoot>/Docs/<DomainName>/` 中由交接包指定的正文；
- 长期程序框架：`<UEProjectRoot>/Docs/ProgramWorkflow/<TaskName>/LongTerm/` 中与当前任务相关的文档；
- 当前批次架构基线：`<UEProjectRoot>/Docs/ProgramWorkflow/<TaskName>/Batches/<BatchName>/ArchitectureBaseline.md`；
- 相关专题结论：当前批次目录下的 `Architecture/`；
- 实际实现：`<UEProjectRoot>/Source/`、`<UEProjectRoot>/Config/` 和任务明确授权的 `<UEProjectRoot>/Content/` 资产。

`<TaskName>` 是当前功能名，`<BatchName>` 是当前批次名。`Planning/<TaskName>/`、`ProjectContext/` 和 `ProgramWorkflow/<TaskName>/Batches/<BatchName>/` 分别表示策划知识、项目当前代码事实和当前批次程序交接；它们不是同一类上下文。

任务上下文包和本次交付默认通过对话传递。只要本次交付要交给 Review 或后续 Agent，架构符合性对应表和实现交接摘要必须进入当前批次 `Implementation/` 下已有的交接文档或总控明确维护的上下文包；不为每个小修复重复创建文档。若本次实现改变公共接口、生命周期、配置边界、正式入口或下游读取所需的实现事实，必须更新当前批次已有的实现交接文档；局部且不影响后续判断的修复可以只通过对话交付。
## 必须读取

- `.codex/skills/ai-native-programming/SKILL.md` 中与当前任务相关的程序约束；

- 总控给出的任务上下文包和架构 Agent 的实现交接包；
- 交接包指定的架构基线章节、项目文档和策划文档；
- 交接包指定的共享功能基线正文；
- 交接包列出的源码、配置、资产入口和验证入口；
- 直接依赖的上游交付摘要。

## 按需读取

- 交接包未覆盖但实现事实确实缺失的接口、Blueprint、资产或源码；
- 与失败复现直接相关的其他产物。

不要默认读取全部策划文档、全部源码、无关模块或其他任务。交接包没有给出代码落点、验证方式或允许的临时适配时，先停止并回交总控，不得通过扩大扫描自行补齐方案。
不要读取其他任务的 `ProgramWorkflow/<OtherTask>/`。
只读取交接包列出的必读文档；按需文档必须先满足触发条件再读取；禁止读取项不得为了寻找捷径而扫描。

## 工作

- 按架构交接包实现任务范围内的代码、必要接入和结构化产物；
- 开始修改前，必须提交“架构符合性对应表”。表格至少包含：架构要求；对应的接口、结构体、模块或代码落点；验证方式；当前状态（满足、允许的临时适配或明确偏离）。任一架构要求没有代码落点、验证方式或明确允许的临时适配时，必须停止并回交总控，不得自行按最短路径实现。
- 对身份模型、请求入口、生命周期、配置边界和 Blueprint 边界逐项建立上述对应关系；明确偏离必须先回交总控，不得静默选择更快的硬编码方案。
- 优先复用已确认接口，保持身份、生命周期、清理和错误结果一致；
- 稳定运行逻辑优先放在引擎原生能力或项目 C++，可变内容放在配置或结构化资产；Blueprint 只承担必要的外壳、组装和资源绑定；
- 对公共接口变化、跨模块修改和临时默认值做明确记录；若影响下游判断，更新实现交接文档。
- 临时测试适配仅能在当前基线允许或总控在授权范围内确认后采用；标注“临时”不豁免现有配置或接口要求。交接说明适用范围、确认依据和替换条件，不得把适配描述成已完成的通用能力。

### 测试样例和内容载体边界

每次实现前，必须把新增内容标记为“运行机制、内容定义、测试适配、表现适配”之一，并确认它通过哪个接口连接。测试样例也必须走正式的请求、结果和事件出口；不能因为它只用于测试，就在通用生命周期代码中加入内容专用分支。

允许暂时把内容数值、结果参数或样例身份写在 C++ 中，但只能放在独立的定义提供器、测试适配器、测试 fixture 或等价边界内。以下做法不合格：

- 在通用请求/生命周期代码中出现某个具体内容标识的分支；
- 在通用组件中直接保存某个内容条目的消耗、冷却或结果强度；
- 让角色、控制器或运行对象直接拥有某个样例的内容规则；
- 用日志或注释声明“临时”，但实际绕过统一接口。

当前不引入 C#、JSON、DataTable 或脚本运行时也可以接受，但必须保留相同的内容定义接口，并在交付中说明将来如何替换当前载体。不要为了证明可迁移而提前引入复杂外部语言；先保证载体可替换、内容与机制已分开。

实现完成前必须做一次静态检查：搜索当前任务的专用身份、数值和结果构造，确认它们只出现在允许的定义/测试边界内；如果架构交付定义了代表性复用案例，说明该案例是否复用同一公共运行路径。

## 停止与回交

若需要改变公共接口、突破模块边界、引入核心 Blueprint 逻辑，或遇到未定义的体验规则，暂停该决策并回交总控。普通编译、类型、include、模块依赖和局部连接错误可以继续修复。

## 交付

返回：实现范围、实际读取的交接包和入口、修改产物、公共接口变化、采用的假设、未实现范围、事实验证入口、结果摘要、已知问题、需要用户判断的问题、项目代码文档影响判断（是否改变模块职责、代码地图、运行入口、配置/资产入口、功能映射或验证方式及其依据），以及实现交接文档是否已更新。实现 Agent 不在 Review 放行前自行更新项目代码文档；不复制原始编译日志或完整运行日志。
