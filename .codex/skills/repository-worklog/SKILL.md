# Repository Worklog

## Purpose

把分散在任务对话和项目产物中的重要工作、讨论与判断整理成简洁的仓库级历史记录，方便人类按时间回顾。工作记录不是完整聊天转录，也不是项目当前架构文档。

## When To Use

仅在用户明确要求以下工作时使用：

- 补充或更新工作记录。
- 整理今天、某段时间或仓库建立以来的重要工作。
- 从本地任务历史中回顾重要讨论和判断。
- 把当前任务中值得长期回溯的内容写入记录。

普通开发、讨论或任务完成不会自动触发记录。

## Record Location

工作记录统一放在仓库根目录的：

```text
docs/worklog/
├── README.md
└── YYYY-MM.md
```

- `README.md` 只说明用途、格式和月份文件索引。
- 每个自然月使用一个 `YYYY-MM.md` 文件。
- 整个仓库共用一套记录，不按项目或主题另建平行日志。

如果目录或当月文件不存在，在用户授权本次记录工作后按上述结构创建。

## What To Record

只记录有长期回溯价值的内容，例如：

- 实际增加、调整或移除的重要能力。
- 项目或工作方向的重要变化。
- 会影响后续任务的方案比较和判断。
- 重要学习结论、失败证据和范围调整。
- 当前已经能做到的程度。

不要记录完整聊天原文、逐文件修改列表、临时尝试、重复结论或普通操作流水。

讨论尚未落地时可以记录，但必须明确它是讨论形成的判断或候选方向，不能写成已经实现的项目事实。

## Entry Format

使用简短条目，不强制增加额外字段：

```markdown
### YYYY-MM-DD：标题

- 内容：加了什么，或者讨论形成了什么重要判断。
- 影响：目前能做到什么程度，或者它怎样影响后续工作。
```

同一天的同一主题优先合并成一条。已有条目能够准确承载新增信息时，更新原条目，不重复创建近似记录。

## Sources And Accuracy

可使用的来源包括：

- 当前对话和用户确认。
- Codex 本地任务历史中的相关对话。
- 仓库内真实代码、配置、资产和文档。
- 日志、测试和实际运行结果。

区分讨论、实施和验证。无法确认日期或完成程度时，使用范围日期或明确标注不确定性，不凭推测补全。

## Relationship To Project Documentation

- 工作记录保存过去发生的重要工作和讨论。
- `project-documentation` Skill 维护项目当前有效的架构、模块、入口和验证上下文。

用户同时要求两类整理时，可以分别使用两个 Skill；不要把历史过程写进模块说明，也不要用工作记录代替项目当前文档。

## Update Workflow

1. 确认用户要求整理的时间和范围。
2. 读取已有 `docs/worklog/README.md` 与相关月份文件；不存在时按固定结构创建。
3. 只检索完成本次整理所需的对话和项目证据。
4. 合并重复主题，写入最小必要条目。
5. 核对日期、项目名称、完成程度以及讨论与事实的边界。
6. 汇报更新了哪些月份文件，以及哪些内容因证据不足未写入。
