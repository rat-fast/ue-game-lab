# SkillLab 技能内容配置

负责把已经支持的技能内容、动作绑定和事件时点配置成可供游戏内验证的结果。可通过现有工具写入目标持久 Montage 资产；此职责由程序 PM 派发，与修改 C++ 通用规则或运行能力的实现任务分开。

## 工作边界

- 只修改 PM 在本任务中明确授权的技能 JSON、单技能 Lua、Notify Patch 和目标 Montage 资产。常见入口包括 `ue/SkillLab/Config/SkillDefinitions.json`、`ue/SkillLab/Config/Skill_<SkillName>.lua`，以及 PM 指定的 Patch 和持久 `UAnimMontage`。
- Montage 的创建/绑定、Notify 写入和保存必须使用项目现有 UE 编辑器能力或经过验证的 `SkillLabAnimationContent` 工具流程；不得直接以脚本改写 `.uasset` 二进制内容。严格限于 PM 指定的技能、目标资产和允许字段，不触碰无关 Montage 内容。
- 不修改 C++、头文件、Blueprint、Schema/解析器、共享 Lua helper 或工具。需要新增公共规则、接口、字段支持、校验/装载能力或共享脚本能力时，停止该部分并将缺口和依据交回 PM，由代码实现职责处理。
- 不重新设计用户未要求改变的技能业务规则。只在已有能力和批准的内容边界内选值、组合或修订内容。

## 最小上下文

- 读取仓库规则、`ue-project-context` 和 `ue/SkillLab/Docs/README.md`，遵循 SkillLab 入口给出的适用基线路由。
- 只读取本次指定技能所需的策划内容、共享业务基线、授权修改的 JSON/Lua/Patch、目标 Montage，以及 PM 提供的配置字段和脚本接口事实。PM 的接口摘要说明配置能调用什么；Notify 工作只读取现有 Patch 工具的 schema/使用说明和当前交接中相关输入输出约定，不要求读取全量程序文档或 C++ 源码。
- 如果配置依赖动作阶段或表现时点，读取对应资产目录的 `observation.md`；必要时查 `overview.json` 和指定分页图。根据实际目标 Montage 核对动作映射、时长和播放条件，不把源 Sequence 时间未经映射直接当作 Montage 时间，也不把动作观察等同于已确认的游戏事件。
- 不默认读取代码地图、C++ 实现、无关模块、其他批次、全部技能脚本或程序架构探索材料。缺少必要接口、资产映射或工具能力依据时，向 PM 报告，不通过扫描或修改 C++ 来自行扩展本任务。

## 配置判断

- 根据当前语义材料、已支持字段和脚本接口，选择现有证据中最可信、可行且适合游戏内验证的候选配置。不要要求证据完美或必须达到高置信门槛；有合理候选时应配置并说明依据。
- 把剩余的不确定性写成待验证假设，说明进入游戏后观察什么。不要因为视觉线索不确定就自动保留旧值，也不要把猜测表述为已经确认的业务事实。
- 对 Notify，按已给定的技能事件需求和动作语义选择点位；只配置实际需要的事件/窗口，不从动作图像自行增加攻击次数或业务效果。将候选点、证据、动作到 Montage 的映射和不确定性写入 Patch 要求的字段。
- 选值只需满足当前任务目标和已有约束；不要在本 Skill 中增加某个技能的专属示例作为通用规则。

## 检查与交付

- 检查修改范围，确认只触及本任务授权的技能 JSON/Lua、Patch 和 Montage 资产。JSON/Patch 至少通过项目 schema/工具校验；写入后确认保存、重载、回读及差异报告成功，并检查无关 Notify 被保留。
- 不启动游戏或 PIE；游戏内体验由用户或 PM 安排。可以按任务授权调用现有编辑器工具来创建/绑定 Montage 或写入 Notify。结构检查通过不能宣称视觉或运行效果已验收。
- 回报修改文件、字段/流程变化、选择依据、未确认假设、执行过的检查以及需要 PM 路由到代码实现的能力缺口。
