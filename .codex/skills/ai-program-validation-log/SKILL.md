# AI 程序验证与问题记录

## 入口关系

本 Skill 由程序工作流总控通过独立本地任务对话调用。进入 UE 项目时，先完成 `ue-project-context` 的项目文档路由，再读取 `ai-native-programming`，最后读取本 Skill。验证对话只记录和归因运行事实，不承担大规模实现。

## 目标

为总控提供可行动的构建、运行和行为反馈，并把需要用户判断的问题与普通代码问题分开记录。本 Skill 不承担大规模实现。

## 项目路径和交接

默认使用以下相对仓库路径：

- 领域验收依据：`<UEProjectRoot>/Docs/Planning/<TaskName>/`；
- 项目运行说明：`<UEProjectRoot>/Docs/ProjectContext/` 中的运行和调试文档；
- 长期验证记录和待判断事项：`<UEProjectRoot>/Docs/ProgramWorkflow/<TaskName>/Validation/`。

`<TaskName>` 是当前功能任务名，策划目录和程序工作流目录必须使用同一个任务名。验证依据来自当前任务的 `Planning/<TaskName>/`，项目运行事实来自 `ProjectContext/`，记录只写入当前任务的 `ProgramWorkflow/<TaskName>/Validation/`；不读取或写入其他任务目录。

一次任务的验证结果先通过对话返回总控；只有需要跨任务追踪、回归或用户回来后继续处理的问题，才写入验证目录。
## 必须读取

- `.codex/skills/ai-native-programming/SKILL.md` 中与当前任务相关的程序约束；

- 本次任务的验收行为和完成边界；
- 相关实现摘要、运行入口和测试地图/配置说明；
- 已有失败记录和需要复现的步骤。

进入验证任务时，先读 `<UEProjectRoot>/Docs/ProjectContext/` 中的项目入口和相关运行说明，再读当前任务的 `ProgramWorkflow/<TaskName>/Validation/`，最后按验收行为读取 `Planning/<TaskName>/` 的相关章节。

## 按需读取

- 复现问题所需的源码、日志、配置、Blueprint 或资产；
- 相关架构约定和模块接口；
- 上一次验证结果与修复交接。

不要默认读取全部代码或全部设计文档，只为复现、归因和确认结果读取最小必要内容。

## 工作

- 记录编译、启动、PIE、日志和可观察行为事实；
- 区分代码错误、集成错误、架构冲突、体验未决问题和验证缺口；
- 为代码/集成错误提供复现步骤、涉及产物和建议处理 Agent；
- 将取消、死亡、重置、目标、施法手感、Blueprint 原则等需要用户判断的问题单独列出；
- 不把一次成功运行写成稳定能力，指出尚未覆盖的场景。
- 将证据至少分成：静态文档/源码证据、编译证据、启动/初始化证据、实际功能运行证据、失败/回归证据。编译成功不能替代功能运行证据，预期日志不能替代实际日志。
- 按当前任务验收清单逐项标记“已证实 / 部分证实 / 未证实 / 本阶段不要求”，并给出实际路径、命令、日志或截图来源。
- 只提供事实证据和可复现的观察结果；不替代架构 Agent 或 Review Agent 判断架构符合性，也不能把编译通过或一次运行成功写成架构通过。

## 交付

使用简短但完整的记录：场景/步骤、预期、实际、证据、分类、涉及模块、是否可复现、建议下一步、是否阻塞当前链路、是否需要用户判断。若只是代码错误，允许总控继续自动安排修复；若是体验或架构选择，保留为待处理事项而不擅自决定。

验证交付不得把“代码存在”“编译通过”或“理论上可运行”写成完整功能已完成。缺少真实运行证据时，必须明确写出证据缺口和最短复现步骤。
