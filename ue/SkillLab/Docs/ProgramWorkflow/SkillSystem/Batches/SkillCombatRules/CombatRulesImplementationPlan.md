# SkillCombatRules 实现准备与验证设计

## 状态与边界

本文是程序 PM 对架构交接的实现准备补充，不是最终 API 命名冻结。操作/打断、缓存、资源/冷却和 Notify/多提交规则已由用户确认并进入实现；受击入口和 Stunned/Silenced 生产授予事实已核实，结果见[实现摘要](Implementation/CombatRulesImplementationSummary.md)。策划需求与源码事实分别以[策划案](../../../../Planning/SkillSystem/Batches/SkillCombatRules/SkillCombatRulesRequirements.md)和[架构交接](CombatRulesArchitectureHandoff.md)为准。

本稿只细化不依赖体验选择的窄契约和验证夹具。实现职责仍建议由一个实现单元完成共享仲裁与 Cast 时序接入，避免 Runtime/Cast 身份接口拆分后无法端到端验证。GAS 状态来源管理不在无新增状态需求时另建系统。

## 核心数据责任

规则评估输入应是一次不可变的运行事实快照，由 C++ Runtime/Ability 从权威对象采集；脚本不得提供或覆盖这些事实：

| 输入 | 含义与来源 |
| --- | --- |
| 运行身份 | 当前 SkillId、RequestId/CastId、活动 Ability 身份及阶段/窗口 token；由 Runtime/Ability 提供，用于拒绝迟到事件。 |
| 当前时序 | 显式语义窗口、已发生的提交点及提交序号；不从 Windup/Active/Recovery 名称推导规则。 |
| 当前状态 | ASC 上有效 Gameplay Tag 快照及必要的状态变化事件；Tag 只提供条件语义，不直接调用取消/拒绝。 |
| 新输入/事件 | 操作类别、事件类别、目标或来源标识、可选受击上下文；瞬时事件与持续状态分开输入。数据由正式输入/战斗入口产生。 |
| 已提交事实 | 是否已扣费、提交点是否已执行、效果请求是否受理；由 Runtime/EffectExecutor/GAS 结果回填，不能由 Lua 声称。 |

规则选择只引用已校验的共享策略及技能差异声明；具体语法和载体由实现依现有 Provider 能力确定。规则结果是一个受控决策和值类型原因，例如允许/拒绝/继续/取消当前 Cast/暂存或丢弃输入意图。结果本身不是执行事实。Runtime 仍负责复核身份、执行唯一终态迁移或提交，正式门控/Targeting/EffectExecutor/GAS 继续产生权威结果。缓存不得直接激活或绕过目标、资源、冷却检查。

已确认规则由共享 Runtime 按操作类别和明确状态/阶段条件执行；本批没有可配置的多规则策略集，不引入额外优先级机制或默认玩法。

## 可先做的实现切片

已确认规则及实现边界如下：

- 以类型化值表达时机窗口、输入/事件类别、决策及拒绝/取消原因；窗口 token 绑定 Cast 身份并在终止时失效。
- 提供纯评估/匹配边界与 C++ 执行边界分离；用户确认策略作为共享规则，不按 SkillId 散落分支。Recovery 内不激活缓存技能；自然结束并退出 Recovery、旧 Cast/Ability 清理完成后才重新消费缓存。
- 闪避意图先取消当前 Cast，再经正式 Ability 激活路径尝试；失败不恢复被取消 Cast。普通受击 Tag 继续 Cast，重击 Tag 取消 Cast。
- 沉默/硬直有效状态既拒绝新技能也取消当前 Cast；程序需把 Tag 输入与 Runtime 规则连接，并报告当前没有已确认的生产授予者。
- 移动与主动取消事件不打断；地面选点 Escape 继续只取消预览。
- 输入使用一个 latest-wins 槽，仅存下一技能意图；Recovery 内不激活。自然完成的 Cast 应将缓存保留到 Recovery 结束后的安全仲裁点；旧 Cast/Ability 清理完成后重新经过 Runtime/GAS 激活、目标、资源和冷却门控，成功才启动下一 Cast，失败报告稳定拒绝原因并清除。取消、死亡、Reset 清空缓存；新 Cast 身份必须独立于旧 Cast。
- 费用与冷却保持在效果/释放提交点；提交前取消不扣，提交后不退款。Notify 超时/Ability 中断取消，不补效果。每 Cast 每提交点至多执行一次，重复事件忽略/拒绝但不取消 Cast。
- 状态读取保持 ASC/GAS 为权威来源；不引入自建 Tag 引用计数器。无 Stunned/Silenced 实际效果来源时，通过测试 fixture 验证 Tag 有效行为，并将生产授予路径标为未覆盖。
- 暴露结构化决策和运行事实以供自动化/既有事件观察；不增加 UI，也不让 Lua 产生受理、命中、效果或终态事实。

实现状态和当前没有生产内容入口的部分见实现摘要；自动化结果不能替代可见 PIE 验收。

## 已确认策略和技术核实项

用户确认策略及需要落实的技术事实：

- 操作与打断：闪避取消当前再尝试激活；普通受击不打断、重击打断；沉默/硬直阻激活并打断；移动与主动取消不打断；Recovery 不接新技能。
- 输入缓存：单槽 latest-wins，只存下一输入意图；Recovery 期间不激活。当前 Cast 自然完成并退出 Recovery 后，待旧 Cast/Ability 清理完成再取出意图并重新经过正式门控；取消/死亡/Reset 清空。门控拒绝时报告原因并清除。
- 资源与提交失败：释放/效果提交点扣费并启动冷却；提交前取消不扣，提交后不回滚；Notify 超时/Ability 中断取消且不补效果；重复提交点只忽略/拒绝、不取消 Cast。
- 技术核实：权威攻击来源如何传递普通/重击类别 Tag；当前没有 Runtime 受击源时接入最小正式事件路径。核实 Stunned/Silenced 有效 Tag 来源；未发现生产授予者时仅能验证门控/打断消费，不宣称有可游玩的状态施加来源。

产品行为已确认。受击分类目前由权威伤害 API 调用者显式传入 Tag；Stunned/Silenced 当前没有生产授予路径。Recovery 不激活新技能，但用户明确要求缓存意图在自然 Cast 完成并退出 Recovery 后重新过正式门控；不得将缓存于自然终止点直接丢弃。
