# SkillLab AI Native 工作流项目上下文

本文只定义项目级角色分工和文档路由，不记录具体技能设计、程序实现细节或历史工作记录。

## 当前定位

SkillLab 使用“共享基线 -> 策划需求 -> 程序/表现实现 -> 独立 Review”的工作方式。主控对范围、顺序、交接和最终状态负责；各专项 Agent 维护自己的职责产物。

## 角色职责

- **主控**：确定任务范围，派发一个完整批次，收集交付，协调冲突，决定是否进入下一批；不把自己的临时判断直接当成共享基线。
- **基线 Agent**：从用户确认、Git 基线、真实代码和验证证据中整理当前共享承诺；区分业务语义、实现事实、当前限制和待确认问题。
- **策划 Agent**：依据当前基线提出玩家可观察需求、资源需求和验收条件；不规定 C++ 类、Blueprint 拓扑或最终资产格式。
- **程序/表现架构 Agent**：把已确认需求转换成职责、接口、配置与资产边界；不替策划确认体验，也不把未来方案写成当前事实。
- **实现 Agent**：在批准范围内修改代码、配置、Blueprint 或资产，并提供可复现验证入口。
- **Review Agent**：独立审查架构符合性、实现正确性和验证证据；未通过时回到当前批次修复。

## 文档路由

1. 读取 `ProjectContext/README.md` 和相关模块事实；
2. 读取相关共享基线，如 `Baseline/CharacterPresentation/` 或 `Baseline/SkillSystem/`；
3. 读取当前任务的 `Planning/<领域>/`；
4. 读取当前任务的 `ProgramWorkflow/<领域>/`；
5. 按交接包读取必要源码、配置、资产和验证证据。

旧批次、归档实验和其他领域的工作流不属于默认上下文。

角色表现当前方向：用户已选择以 Lua 作为试点脚本语言。此决定记录项目方向，不代表脚本运行时、UE 接入方案或具体迁移范围已经确定或验证。
