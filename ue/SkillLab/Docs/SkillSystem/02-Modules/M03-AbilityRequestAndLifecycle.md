# M03 技能定义、请求与施法生命周期（详细设计草稿）

## 定位与状态

M03 定义一次技能调用如何从请求进入能力系统，如何进行激活判断、创建运行实例、推进阶段、消耗资源、启动冷却、取消、打断、结束和清理。

已确认：技能定义与施法实例分开；玩家、AI、测试最终共享施法请求后的规则；需要前摇、引导、多段、取消、打断、冷却、资源和缓冲的扩展位置。
AI 建议默认方案：扣费时点、冷却时点和缓冲规则需要结合首批样本试玩确认。

## 一、职责边界

M03 负责：

- 技能定义读取和技能身份确认；
- 施法请求的统一接收、拒绝、缓冲和结果；
- 激活条件检查；
- 施法上下文和施法实例；
- 前摇、释放、引导、收招、多段阶段推进；
- 资源扣除、冷却启动和取消/打断清理的公共时序；
- 向目标、效果、执行载体、表现和日志发布阶段事件。

M03 不负责：

- 输入按键和槽位装配；
- 具体空间碰撞和投射物运动；
- 伤害或治疗数值计算；
- UI 自己判断可用性；
- AI 决策。

## 二、关键对象

技能定义是可重复使用的内容描述，包括目标需求、输入模式、阶段时间、资源/冷却配置、取消与打断规则、执行模板、效果组合和表现事件引用。

施法请求是一次具体调用尝试，至少包括来源、施法者、技能身份、目标参数、请求时间和追踪信息。请求可以被拒绝、缓冲或开始。

施法上下文是从请求带入执行的施法者、技能身份、目标解析、位置方向、来源、按需快照和实例身份。

施法实例是一次已经开始或正在处理的运行生命周期，关联阶段、临时对象、命中、效果、取消/打断原因和结果。

## 三、统一请求结果

请求结果至少区分：

- Rejected：未开始，原因如死亡、冷却、资源不足、目标无效、状态阻塞；
- Buffered：暂未开始，已保存，等待重新检查；
- Started：已进入施法实例；
- Interrupted：已经开始，因死亡、受击、取消或规则中断；
- Completed：达到结束条件；
- Cancelled：已经开始或正在预览/执行阶段，被明确取消；
- Expired：缓冲或目标上下文过期。

失败尝试是否分配内部对象由程序决定，但对外必须能区分未开始和开始后终止。

## 四、推荐运行链

提交请求
→ 校验技能身份和施法者
→ 检查状态、资源、冷却和目标
→ 拒绝或进入缓冲
→ 通过后形成上下文并开始实例
→ 按阶段执行前摇/释放/引导/收招
→ 调用 M04 查询/命中，调用 M05 应用效果
→ 发布表现和结果事件
→ 完成、取消、打断或重置清理

激活检查必须在请求进入、缓冲重试和真正开始前都可重复执行。UI 预览通过不代表激活一定成功。

## 五、资源、冷却和阶段时点

这是首批需要用户重点确认的系统规则。建议默认：

- 资源在激活成功、施法正式开始时扣除；
- 冷却在激活成功时启动；
- 前摇中取消是否退款，默认不退款，由技能定义声明例外；
- 前摇被打断是否进入冷却，默认进入，具体技能可声明；
- 引导技能可按阶段消耗或只在开始消耗，但必须统一记录；
- 多段技能的每段命中不重复扣除启动资源；
- 资源不足、冷却中和状态阻塞属于未开始拒绝。

激活成功、第一段命中、前摇结束不能在不同技能里无说明地混用。技能定义要声明特殊时点。

## 六、取消、打断和重置

区分：

- 预览取消：没有施法实例，不产生效果；
- 请求拒绝：没有开始运行；
- 已开始取消：实例结束，执行取消清理；
- 受击/死亡打断：实例中断，发布原因；
- 场景重置：强制结束所有实例并清理临时对象、监听器和计时器。

默认情况下，取消/打断不会自动撤销已经应用的伤害或状态；持续效果是否移除由效果归属规则决定。清理必须幂等，不能重复结算或重复触发结束事件。

## 七、输入缓冲

首版建议只支持可选的单次缓冲：

- 保存最近一个符合条件的请求；
- 缓冲有过期时间；
- 新请求覆盖旧请求；
- 死亡、重置和明确失去行动资格时清空；
- 重新尝试时重新检查所有激活条件；
- 换装后旧请求不能改调用新槽位技能。

不把多条连招命令队列作为首版默认能力。缓冲容器由程序实现；适用动作、时长和覆盖规则属于项目默认配置。

## 八、配置、固定约束与程序自由

可配置：阶段时长、资源类型和数值、冷却、取消窗口、可被哪些状态打断、输入需求、缓冲策略、执行模板和结果事件。

固定约束：

- 请求不能绕过激活判定；
- 技能实例必须保留技能身份和施法者；
- 失败/取消/打断/完成结果可区分；
- 清理可重复调用而不重复结算；
- 资源、冷却、效果和临时对象的归属可追踪；
- 结束不等于强制销毁所有外部对象，外部对象必须有明确归属和结束规则。

程序可选择 GameplayAbility 生命周期、任务、标签、句柄和内部状态机的具体组合。

## 九、观察点与待确认

需要记录请求来源、拒绝原因、阶段切换、资源扣除、冷却启动、命中、效果、取消/打断和清理结果。

用户重点确认：

- 资源在开始、命中还是其他时点扣除；
- 冷却在开始、结束还是其他时点启动；
- 前摇被打断是否进入冷却；
- 引导和多段如何处理资源；
- 单次输入缓冲是否首版启用。

## 十、模块交接

- M01 提供装配后的技能身份和目标参数；
- M02 提供有效单位、能力身份、状态和重置信号；
- M04 提供目标解析与命中结果；
- M05 提供资源读取和效果应用；
- M06 执行投射物、区域、位移和空间阶段；
- M07 订阅阶段与结果事件；
- M09 记录全过程并提供重置观察。
