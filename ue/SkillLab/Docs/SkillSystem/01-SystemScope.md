# 技能系统目标与范围

## 文档定位

本文档是 SkillLab 技能系统文档的第一层：**系统目标与范围**。

它只回答四个问题：

- SkillLab 为什么需要技能系统；
- 这套系统面向什么运行场景和生产目标；
- 第一阶段要覆盖到什么程度；
- 哪些内容明确不属于当前基础系统。

本文档不定义具体 C++ 类、GAS 类图、技能参数、效果结算细节、最终配置格式或完整验证流程。相关内容进入第二层总览、模块设计与公共约定，以及程序结构和验证文档。当前产物地图见 [技能系统索引](README.md)。

## 项目背景

SkillLab 是一个用于验证 Unreal Engine 游戏研发流程和 AI 技能生产能力的实验项目。当前项目已有基础运行基线：`GameMode`、`PlayerController`、`Character`、点击移动、导航查询和调试反馈已经存在；战斗和技能系统尚未接入。

SkillLab 不以制作完整商业游戏为目标，而是希望在一个边界明确的技能领域内，验证从技能意图到运行时执行、反馈和迭代的完整链路。

## 系统定位

SkillLab 要建立一套**面向当前项目战斗场景、以 GAS 为主要运行基础、可持续扩展的技能系统底座**。

它不是：

- 面向所有游戏类型的通用 GAS 框架；
- 只验证一个伤害技能的技术演示；
- 把完整职业、装备、成长和关卡设计一次性写死的商业游戏框架；
- 要求所有技能都通过最终 DSL 或纯文本直接生成的系统。

它应当服务于当前方向：

- 单机实时战斗；
- 俯视角；
- 操作层偏 MOBA；
- 技能和效果丰富度偏 ARPG；
- 玩家、敌人和友方单位共享基本能力规则；
- 玩家输入、AI 决策和测试工具可以逐步接入同一套技能运行能力。

## 第一阶段目标

第一阶段的目标不是一口气实现所有高级玩法，而是建立一组相对稳定的核心能力，使后续技能可以在共同底座上扩展，而不是每增加一种技能就重写 Character 或 PlayerController 中的专用逻辑。

首版系统需要从整体上纳入以下能力范围：

### 单位与能力基础

- 战斗单位、阵营、生命、死亡和重置；
- `AbilitySystemComponent` 的初始化、能力授予、移除和清理；
- 属性、资源和属性修改；
- 能力激活、失败、取消、持续和结束；
- 冷却、资源消耗和基本状态门控。

### 技能执行形式

- 瞬发效果；
- 前摇、延迟和收招；
- 持续引导和多段生效；
- 直接命中；
- 投射物；
- 单体和范围命中；
- 直线、扇形和持续区域；
- 位移。

### 效果与状态

- 伤害、治疗和护盾；
- 增益和减益；
- 减速、眩晕、沉默、定身等控制；
- 驱散、免疫和状态移除；
- 瞬时、持续和周期效果；
- 效果叠加、刷新、覆盖和独立计时的扩展位置。

### 目标与交互入口

- 自身目标；
- 单体单位目标；
- 地面位置目标；
- 方向目标；
- 敌方、友方、自身和中立目标过滤；
- 玩家、AI 和测试工具的统一施法入口；
- 按键、输入动作、槽位与技能装配分离；
- 运行中通过简单 UI 选择槽位并更换技能，查看冷却和不可用原因；
- 施放前的目标预览、确认与取消，直接施放入口可按规则跳过预览。

### 运行与观察

- 动画、特效、音频和 UI 的表现事件入口；
- 投射物、持续区域、监听器和计时器等临时对象的生命周期；
- 施法阶段、目标、效果和失败原因的可观察记录；
- 取消、死亡、重置后的状态和临时对象清理。

这些内容属于首版总体设计范围，但不要求在同一时间全部实现完毕。实现可以分阶段推进；分阶段只表示交付顺序，不表示后续能力可以在架构上完全不考虑。

## 明确暂不纳入的范围

以下内容不是当前基础系统的首版目标：

- 完整商业职业体系、装备、天赋、经济和成长循环；
- 多人网络预测、回滚、权威同步和网络技能复制；
- 任意脚本化技能和无限自由组合；
- 格斗游戏级逐帧连招和取消体系；
- 复杂召唤、变身、多阶段技能和高阶链式规则；
- 为所有未来游戏类型提供通用战斗框架。

暂不纳入不代表永久排除。后续如果真实技能样本证明这些能力有必要，再以扩展需求的形式进入能力模型和程序结构设计。

## 首版的成熟度定义

首版达到的目标是：

> 建立一组足够稳定的核心能力和扩展边界，使系统能够持续承载多种技能执行形式与效果组合，并允许玩家、AI 和测试工具逐步共享这些能力。

首版不要求：

- 所有列出的技能形式都已拥有完整内容样本；
- 所有高级规则都已经最终定稿；
- 最终内容 DSL 已经确定；
- 完整商业游戏循环已经存在。

“稳定”在本文档中的含义是：新增技能主要通过已有能力和明确扩展点组合完成；需要新增 C++ 能力时，系统能够识别并记录能力缺口，而不是让内容作者绕过公共框架写专用逻辑。

## 文档交接边界

本层之后按以下产物分工，不要求依次全部写完才允许开发。原“第三层公共语义”纳入第二层模块设计与共享约定，当前模块地图以索引为准：

| 后续层级 | 负责的问题 |
|---|---|
| 第二层总览 | 稳定概念、模块职责、依赖和完整链路。 |
| 第二层模块设计与公共约定 | 各模块的可落地流程、配置、固定约束与默认规则；跨模块规则集中维护。 |
| 配套：技能执行模板 | 瞬发、投射物、范围、持续区域、引导和位移等形式如何复用公共语义。 |
| 配套：代表性技能与角色样本 | 用具体样本推动实现、试玩和规则修正。 |
| 配套：程序结构映射 | GAS、C++、配置、Blueprint、表现和测试模块如何承载前述概念。 |
| 配套：验证与内容生产接口 | 如何观察、修改、重置、回归和批量生产技能，以及 AI 的操作边界。 |

## 第一层的完成标准

第一层在以下问题得到同意后即可冻结为阶段性基线：

1. 系统定位是否准确：既不是通用所有游戏的框架，也不是单个技能演示；
2. 首版成熟度是否准确：核心能力相对稳定、可扩展，但不要求一次完成全部高级内容；
3. 首版总体能力范围是否包含投射物、范围、持续区域、引导、控制、驱散、位移和表现事件；
4. 暂不纳入的范围是否足以控制当前项目边界；
5. 后续文档的职责是否清楚，避免把不同层级继续混写。

第一层冻结后，仍可以根据第二层和实际运行结果回写范围，但任何范围变化都应记录为新的假设或版本调整。

## 当前状态

### 已确认

- SkillLab 需要建立相对稳定、可扩展的技能系统底座；
- GAS 是当前主要运行基础方向，但具体职责分工仍需通过后续能力模型和程序验证确认；
- 首版总体设计需要覆盖多种技能执行形式和效果类型；
- 实现可以分阶段，整体能力范围不能因此被缩窄；
- 当前系统服务于 SkillLab 的单机俯视角实时战斗实验，而不是所有游戏类型。

### 当前假设

- 玩家、敌人、友方单位和测试工具将逐步共享能力规则；
- 内容生产会优先使用结构化、可读取和可回滚的表达方式；
- 代表性技能用于边做边发现系统缺口，不作为必须完成的固定验收关卡。

### 待后续文档确认

- 能力、效果、状态、施法实例、目标和运行时对象的具体概念边界；
- 默认激活、目标、时序、取消、叠加、所有权和重置规则；
- GAS 原生能力与 SkillLab 项目能力的具体映射；
- 内容配置、资源绑定、表现事件和验证接口的最终形式。
