# 请求与施法生命周期

## 职责

本页定义一次技能请求从提交、门控、施法阶段、释放、执行到完成或取消的业务行为。它描述施法身份、阶段和资源承诺，不规定具体技能的命中方式。

## 当前生命周期

一次有效请求按以下链路运行：

```text
提交请求
→ 识别技能并检查施法者状态、授予资格、冷却、能量和目标
→ 建立一次施法并进入前摇
→ 释放前再次检查施法者状态、目标和能量
→ 进入生效阶段并提交能量、冷却
→ 由技能行为完成命中/效果处理
→ 进入收招
→ 完成
```

提交时会分配请求身份；通过初始门控后才建立本次施法身份。单位同一时间只能有一个进行中的施法，已有施法时新请求会以忙碌拒绝。未知技能、未初始化、施法者不匹配、技能未授予、死亡或被阻塞、冷却中、能量不足、目标无效等情况都会在产生施法身份前拒绝。

当前阶段有 `Windup`（前摇）、`Active`（生效）、`Recovery`（收招）以及 `Completed`、`Cancelled` 两个终态。阶段变化后，已经过期的旧结果不能推进当前施法或影响新施法。释放是一次施法中的单次承诺，不能重复提交资源或重复进入生效。

## 释放和阶段完成

当前支持两类释放来源：按前摇时长自动释放，或等待指定的技能事件释放。事件驱动的前摇有超时保护；超时后施法取消。进入 `Active` 后，技能行为可以立即完成，也可以等待命中、阻挡、过期或其他行为结果。配置了收招时，生效阶段不能直接跳过收招；没有收招时，行为可以直接进入完成。

进入 `Active` 前会再次确认施法者仍存活且未被阻塞，并再次确认目标仍满足技能要求。确认通过后才扣除能量并开始冷却。前摇中取消不会提交这两项资源承诺；释放后取消默认不返还已经提交的能量和冷却。技能行为自身的命中失败、目标为空或投射物过期属于施法已释放后的结果，不会把已提交的资源恢复成未提交状态。

## 取消与中断

进行中的施法可以被显式取消，也可以因以下状态变化取消：

- 施法者死亡；
- 技能定义声明的阻塞状态出现。当前四个技能均声明死亡、眩晕、沉默为阻塞状态；
- 技能能力提前结束；
- 释放事件超时、行为明确失败或行为无法创建；
- `Reset` 或世界结束清理。

取消会终止当前阶段和正在进行的技能动作，并发布 `Cancelled`。取消后的施法不能再次释放、完成或重复取消。完成和取消是互斥终态；完成会发布 `Completed`，并在有收招时等待收招结束后才发布。

命中未发生、范围内没有目标或投射物自然到期属于技能行为结果，当前会报告未命中并完成施法，不自动把它们视为取消。

## 资源、冷却与施法身份

技能定义提供能量消耗、冷却和阶段时长。资源与冷却属于一次施法在释放时的承诺，而不是请求刚提交就立即消耗。结果和事件会带有请求身份、施法身份、阶段、来源、目标和原因，便于区分同一技能的不同使用及其后续结果。

## Reset（系统重置/测试语义）

`Reset` 是用于系统重置和测试运行的操作，不是玩家技能玩法规则。它会取消当前施法，移除当前持续效果，清除技能冷却，并将生命和能量恢复到各自上限；不会撤销技能授予关系。重复执行不应遗留上一轮施法、冷却或持续效果状态。

## 当前限制

- 当前只承诺单机本地的一次施法流程，不承诺网络同步、输入缓冲或资源退款规则。
