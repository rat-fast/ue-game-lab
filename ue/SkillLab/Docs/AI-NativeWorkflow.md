# SkillLab AI Native 工作流定位

## 文档职责

本文档记录 `SkillLab` 作为技能领域实验项目的范围、假设、证据和下一步。跨项目原则以仓库根目录 `AI_NATIVE_GAME_DEV_PRINCIPLES.md` 为准；历史对话索引见 `docs/AI Native对话与决策索引.md`。

## 项目目标

验证 AI 能否在一个边界明确的技能领域内，完成从意图理解、机制拆解、内容生产、UE 接入、运行验证到迭代反馈的部分或完整闭环。

项目不以制作完整商业游戏为目标，也不以“让 AI 逐节点操作 Blueprint”作为主要研究路线。

## 当前阶段

当前处于“运行基线已建立、技能生产接口尚未定型”的阶段：

- 项目自己的测试地图、GameMode、Character、PlayerController 和导航反馈已经存在。
- `L_SkillLab_NavTest` 可用于重复进入 PIE、控制角色和观察成功/失败反馈。
- 当前没有接入 GAS，也没有锁定外部 JSON、DataTable、DataAsset、DSL 或脚本为最终内容格式。
- 当前优先任务是接口审计，而不是先重做完整技能框架。

## 工作流假设

```text
技能意图
→ 技能规格
→ 机制、时序、目标、效果和表现需求
→ 运行时可执行产物
→ UE 中运行
→ 日志、状态、截图或其他反馈
→ 诊断、修改和回归
```

其中：

- C++ 倾向承载稳定的运行能力、校验、日志和测试入口。
- 配置或结构化数据倾向承载参数、资源引用和可重复内容。
- 复杂行为组合是否需要 DSL、行为图、可执行 IR 或受限脚本，必须由真实技能任务证明。
- Blueprint 继续承担兼容外壳、资源绑定、组件组装和 UE 必需的对象关系。
- GAS 是候选运行后端，不是当前阶段的必选前置条件。

## 代表性技能的选择标准

首个基准技能应至少覆盖其中多数链路：

- 输入和激活条件；
- 目标查询；
- 前摇或延迟；
- 飞行物或范围命中；
- 伤害或治疗；
- Buff/状态及持续时间；
- 命中或结束事件；
- 最小动画、特效、音频或 UI 反馈；
- 可重复施放、重置和日志观察。

它的作用是暴露生产接口瓶颈，不是追求一次做出完整商业技能。

## 接口审计记录要求

对每个技能产物记录：

| 维度 | 要回答的问题 |
|---|---|
| 可理解 | AI 是否能准确知道该产物表达的业务语义？ |
| 可读取 | AI 能否稳定获得当前状态、引用和依赖？ |
| 可修改 | 修改是否需要图形界面、逐节点操作或不稳定资产操作？ |
| 可验证 | 是否有日志、状态、自动校验、截图或 PIE 证据？ |
| 可回滚 | 是否能看到 diff、恢复旧版本并定位来源？ |
| 下游影响 | 修改后会影响哪些代码、资产、关卡或表现？ |

审计结果应区分“AI 能改”和“值得让 AI 改”。

## 当前不做的事

- 不因为 AI Native 的目标就整体删除已有 Blueprint。
- 不在没有代表性技能和失败证据前引入完整脚本运行时。
- 不把一次可运行演示写成稳定生产能力。
- 不把外部购买或下载的美术资源直接当作项目自有资产；来源、许可证和派生关系需另行记录。
- 不把 SkillLab 扩大成第二个完整游戏，以免学习、框架建设和工作流研究互相混淆。
