# 01：技能系统空间配置支持

## 1. 目标与任务边界

**状态：细化需求修订稿，供用户审阅，尚未进入实施。**

让内容配置者能够表达“哪个对象，在什么事件发生时，相对谁出现在什么位置、朝向和大小，之后是否继续跟随”，由游戏运行机制正确执行。这项能力服务于[批次目标与共用边界](README.md)，适用于已有基本功能、动作和释放时点的内容。

程序需核对现有支持，复用可用部分，补齐缺少的配置表达、运行功能与正式入口接入。交付应是实际可用的能力，不止是现状调查或配置字段列表。

**交付对象是可供不同角色、技能和资源复用的空间配置功能，四技能只是接入与验收案例。** 对同类空间行为，新增技能、换模型绑定、换资源或调整参数，应通过 Lua 内容与文本配置完成，不要求修改通用 C++，也不能通过按四技能名称分支的方式实现。新增真正不同的运行机制时才讨论 C++ 扩展，不承诺覆盖本轮未提出的全部未来行为。

本任务不负责数据导出工具、AI 读取空间材料、选择最终美术参数或完成全部技能的视觉适配。这些分别属于本批 02—04；本任务可使用明确指定的测试参数独立验证。

### 已有基础与本轮增量

下表依据共享基线和模块文档，说明复用前提；未核对源码，不将文档未提及的空间能力直接判为不存在。

| 已有基础 | 本轮工作 |
| --- | --- |
| Lua 技能定义、JSON 参数与加载后的运行定义 | 为适用对象补齐空间语义、绑定与参数的表达和读取，不重做内容加载系统。 |
| 请求、Cast、Notify/Gameplay Event 正式释放和提交链路 | 在对应事件/执行点消费空间定义，不重新设计激活、释放时点或战斗规则。 |
| 投射物、地面范围、即时目标执行及伤害/治疗/持续效果 | 为真实生成位置和对应表现补空间控制，不重建这些技能执行与结算功能。 |
| 角色动作播放、技能事件路由与占位反馈 | 模块文档记录结果/持续效果在 Lua 中主要记日志、占位反馈由 C++ 路由执行，尚无正式差异化 VFX 编排；复用事件和来源，补最低限度的可配置表现创建、放置、跟随与结束接入。 |

表现侧本轮只要求能够按所列事件消费空间定义，创建或复用适用可见对象并管理其空间关系和寿命；现有承载不足时补必要通用能力，用现有资源或最小替代对象验证。不建设通用特效编辑器、完整演出编排或正式美术资源库。

## 2. 配置作用于什么

空间配置应能定位到具体技能中的具体对象及其出现事件。一个技能的投射物、释放表现、命中表现或持续效果表现可以有不同配置，不能因修改一个偏移就使其他对象一起移动。按实际存在或本任务验证需要的对象接入，不要求每个技能预建全部表现阶段。

区分两类对象：

- **真实执行对象**：例如 Fireball 投射物。配置参与实际生成位置计算，可能影响后续轨迹与碰撞，需要进入正式技能执行链。
- **表现对象**：例如地面范围表现、自疗反馈或持续效果附着物。配置改变呈现方式，不产生伤害、治疗、命中或持续状态事实。

表达一次适配时，应能辨明：使用的对象/资源、触发它的既有事件、位置参照、偏移、方向、视觉尺寸及后续跟随关系。以上是功能语义，不是要求建立这些同名字段，也不指定配置文件格式。

## 3. 必须支持的空间语义

### 位置参照与偏移

支持以施法者、当前目标、技能已有地面作用位置或明确关联的对象作为位置来源；对于有模型的来源，支持选择模型原点、骨骼或 Socket 等适用参照。位置来源只消费既有目标/作用位置，不重新选择目标。

配置中必须区分以下偏移含义：

| 偏移参照 | 运行含义 |
| --- | --- |
| 来源局部空间 | 沿所选参照的轴偏移；参照转向时，偏移方向随之改变。 |
| 世界空间 | 沿世界固定方向偏移，不随角色转向。 |
| 技能执行方向 | 沿既有执行方向确定前方偏移；例如从手部参照沿发射方向向前移，而非沿手骨自身朝向移动。 |

每项配置使用明确的偏移参照，不要求任意叠加所有坐标空间。具体 UE 变换组合由程序设计，但实际结果必须符合选定语义。骨骼/Socket 名称可由后续配置 AI 选择，不要求用户手工提供。

### 方向与资产朝向修正

位置来源与方向来源分别确定。支持使用既有技能执行方向、所选参照朝向或明确的世界朝向；只在有对应方向语义的对象上使用，不给无方向的即时效果强加朝向。

支持修正资产自身朝向，使其可见主体与期望方向一致。真实投射物的飞行方向与可见模型的朝向修正必须区分；修正模型朝向不能暗中旋转碰撞体、改变瞄准规则或飞行轨迹。

### 视觉尺寸

支持独立调整被配置对象的视觉尺寸，至少满足整体缩放。调整应作用于预期的可见主体，不因 UE 的父子缩放关系而无意改变碰撞体或其他关联对象。

AreaBurst 的实际作用范围由既有技能规则决定，表现尺寸可据此适配；Fireball 可见主体的缩放不自动放大其碰撞尺寸。资源确实需要非等比调整等额外能力时，按具体需求补充，不默认建设任意变形能力。

### 一次求值与持续跟随

| 关系 | 运行含义 |
| --- | --- |
| 一次生成/放置 | 在实际触发或生成时取得参照并计算变换，不沿用施法开始时的过期位置；生成后不再因参照移动而被拖动。真实投射物随后按既有执行行为运行。 |
| 持续跟随/附着 | 出现后持续维持所选空间关系；支持位置跟随，并明确方向是随参照变化还是保持出现时的世界朝向。 |

跟随的每次位置更新继续使用已选偏移参照。附着后的视觉尺寸应维持配置预期，不因父对象缩放而无意改变。具体采用 UE 附着、运行更新或其他方法，由程序决定。

## 4. C++、Lua、JSON 的分工与运行接入

### 本轮要求的分层

以下是本需求的职责要求，不只是技术候选；具体类、模块拆分、API 与字段由程序设计。

| 层                 | 必须承担的内容                                                                             | 内容变化时的边界                                                      |
| ----------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| C++ 稳定运行能力        | 受控解析角色/目标/地面来源和模型参照，提供坐标变换等基础运算；执行真实生成、表现创建/变换应用、持续附着、来源隔离、有效性检查及清理；在正式链路中消费最终空间结果。 | 表达可复用机制，不识别四技能名称来决定偏移、Socket、资源或专属表现。                         |
| Lua 内容与空间组合       | 声明某内容在什么既有事件使用哪个空间行为，选择位置/方向来源与一次求值或跟随关系；利用受控信息和基础运算组合任务需要的条件、偏移及尺寸计算。              | 能为新内容组合已有机制，不直接取得任意 Actor/ASC、绕过目标和提交规则，也不复制 C++ 的生成、校验与寿命管理。 |
| JSON 高频参数与资源/模型绑定 | 保存需要独立调整的偏移值、朝向修正、视觉比例、资源引用，以及具体模型对应的骨骼/Socket 等绑定；供 Lua 定义和运行能力读取。                 | 不保存逐次采样的世界坐标作为通用起点，不承载条件分支、逐帧执行或生命周期逻辑。具体文件组织沿已有内容入口扩展。       |

例如“在释放事件取施法者的已绑定手部参照，沿既有发射方向前移，再生成投射物”：事件与来源/运算组合由 Lua 内容表达；绑定、前移量和视觉修正参数由 JSON 承载；实时查询、基础变换、正式生成与检查由 C++ 执行。这不是要求每项简单变换都写一段独立 Lua，允许复用已有组合。

Lua 所需空间信息和操作应通过业务宿主提供受控能力；当前宿主支持到什么程度由程序核对，缺口属于本任务。公共 Lua Runtime 继续只负责语言运行设施，不把技能空间业务加到公共 VM 模块。持续跟随交由 C++/UE 的运行机制维护，本轮不要求新增常驻协程或逐帧 Lua 回调。

每项定义、绑定与参数只保留一个权威来源，不在 Lua、JSON 与资产中重复手填同一值。角色模型改变时允许更新绑定数据，不要求通用运行代码增加角色专属分支。

### 正式接入位置

空间适配本身不要求新增 GAS Ability、GameplayEffect 或 Gameplay Cue；已有 GAS 激活和结算职责继续复用，是否需要局部配合修改取决于实际接入。各层应在职责匹配的现有链路接入：

| 职责      | 本任务要求                                                               |
| ------- | ------------------------------------------------------------------- |
| 技能激活与释放 | 沿用现有门控、Cast 身份、Notify/Gameplay Event 释放信号和提交规则，不新增绕过正式释放的触发路径。      |
| 真实对象执行  | 在正式生成对象时解析并消费空间定义；不能只移动其装饰表现，而真实投射物仍从旧位置生成。                         |
| 表现响应    | 根据真实技能事件定位施法者、目标或作用位置，执行对应表现的空间定义；不反向裁定业务结果。                        |
| 空间解析与计算 | 支持实际模型参照与配置语义，可供执行和表现使用；是否需要新增公共能力由程序核对，避免各处另造不一致算法。                |
| 可变内容    | 按本节明确的 Lua 内容/计算与 JSON 参数/绑定分工，沿已有内容入口扩展。 |

持续附着由具有相应对象寿命的运行机制维护，不能假定当前一次调用式 Lua 或原施法 Ability 永远存活。已交付投射物、持续效果和施法动作各自遵循既有生命周期：动作结束不等于持续效果移除，Cast 结束不应错误销毁已独立交付的对象。

配置按实际施法/对象来源关联，旧施法的更新或清理不能移动、删除新施法的对象。持续表现消费相应效果的真实移除事实；参照或所属对象失效时停止无效跟随并清理相应表现，不据此擅自撤销已生效的战斗效果。

## 5. 内容接入、修改与失败反馈

### 样本接入

以下检验共同能力是否进入真实内容，不是四套专用实现。当前不要求完成四技能的最终空间参数和正式美术质量，那属于后续适配任务。

| 样本 | 本任务中的接入要求 |
| --- | --- |
| Fireball | 真实投射物生成位置可配置；生成时求值，方向遵循既有执行规则，支持视觉朝向和整体尺寸修正。检查起点变化对相关轨迹、遮挡与近墙发射的影响。 |
| AreaBurst | 地面表现以技能已有作用位置为参照，支持偏移、方向及视觉尺寸；不移动或扩大实际伤害区域。 |
| Mend | 自疗仍作用于自身；对现有可适配反馈提供独立空间定义，验证自身体或相关部位参照，不预设必须持续附着。 |
| BurningBuff | 持续伤害仍作用于既有敌方目标；对持续状态表现支持目标侧参照及适用跟随，生命周期对应效果事实而非施法动作。 |

程序需核实现有表现对象及支持缺口。缺少适用表现资源时，可以用最小替代对象验证上述能力，标明替代范围；不在本任务制作正式美术或改变技能玩法。其他关联对象/武器可复用同类空间语义，不要求新增武器战斗系统。

### 配置入口与生效确认

- 配置须有 AI 可读、可定位、可修改的权威入口，能按技能和对象识别当前值及参照语义，避免文本与 UE 资产各自手工维护同一值。
- 说明修改后通过何种现有加载、重载或重启步骤生效；本需求不强制热更新。后续新执行使用何份定义应可确认，正在运行的对象遵循已有快照/更新约定，不无意混用不同版本。
- 能回读实际采用的对象、空间定义和运行条件。最小生效确认属于本任务；批量画面导出、测量与可视对照工具留给 02。
- 未配置新适配内容时，保持现有有效内容的原行为。显式配置了无效参照、缺失资源或无法求值的方向时，应报告技能、对象及原因，不能静默落到世界原点并宣称成功。
- 纯表现失败不得改变技能权威结果。真实投射物生成失败接入现有执行/提交失败处理，不新增自动成功、补发或退款规则；现行规则不足以决定处理时，交回具体业务缺口。

## 6. 验收与交付

本任务使用预先指定的有效参照及明显可辨的测试配置验证能力，不要求先完成 AI 自主选点。精度按具体查询和运行条件说明，不设通用厘米或审美阈值。

| 场景 | 操作及预期结果 |
| --- | --- |
| 对象独立配置 | 修改一个对象的偏移或尺寸，实际生效且其他未修改对象维持原配置。 |
| 坐标参照 | 改变角色位置和朝向，分别使用局部、世界和执行方向偏移，观察结果符合第 3 节定义。 |
| 实时生成点 | 施法开始后改变角色/手部姿态，在既有释放点生成；位置使用生成时参照，生成后对象按既有行为独立运行。 |
| 位置与方向分离 | 位置取手部，方向遵循既有技能执行方向；模型朝向修正和视觉缩放不无意改变轨迹、碰撞体及伤害。 |
| 地面表现 | 对 AreaBurst 改变表现偏移和尺寸，实际作用位置与范围仍遵循原规则。 |
| 持续跟随 | 用适用样本或替代对象检查移动、转向和相关动作过程；位置及方向跟随关系正确，效果结束或参照失效后无悬挂对象和无效更新。 |
| 生命周期与身份 | 施法结束后，已交付投射物或持续效果按既有寿命运行；结束一个来源不误清理另一个来源的对象。 |
| 真实起点边界 | 对 Fireball 检查相关近墙和遮挡情境；记录真实生成结果及轨迹/碰撞影响，不通过穿墙、改碰撞策略等方式绕过问题。 |
| 修改与失败 | 按说明加载新配置并回读；无新配置保持原行为，无效显式配置得到具体反馈，不伪装成正确生成。 |
| 同类内容复用 | 基于已支持行为增加一项不同内容标识的测试定义，仅通过 Lua 与 JSON 接入；更换适用模型绑定或表现资源，再验证同类空间关系，不新增按技能/角色名判断的 C++ 分支。可以复用现有测试定义，无需新增正式玩法技能。 |
| 分层可调整性 | 改 JSON 偏移/尺寸/绑定不改 C++；用 Lua 改已有空间能力的来源或运算组合不改通用内核。确认持续跟随仍由运行机制维护，Lua 不越过正式执行/结算边界。 |

本轮须交付三类结果：

1. **通用运行能力**：实际生成点、表现放置与跟随等能力在正式链路可用，并有明确的 C++/Lua 边界及错误反馈。
2. **可使用的内容入口**：Lua 声明/组合与 JSON 参数/绑定的用法、样例和生效确认方法；后续配置 AI 据此工作，不必修改通用源码。
3. **接入与验证证据**：已有支持及补齐项、四样本的实际接入或替代限制、同类内容复用与分层验证结果、未完成事项。

仅列字段、编译通过、保存四份配置或四技能各自能跑，不等于通用能力交付。验证范围限于相关功能及直接受影响链路，不重开全部技能功能回归。
