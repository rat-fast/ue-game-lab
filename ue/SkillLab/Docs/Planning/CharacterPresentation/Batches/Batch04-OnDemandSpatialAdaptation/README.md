# Batch04：按需空间适配

## 目标与当前状态

面向大量角色与技能的俯视角 ARPG，在内容已有基本功能、动作和大致释放时点后，让 AI 按具体任务完成空间适配与表现细化。对象包括实际投射物、特效、武器等，不限于当前四技能。

本批拆为四项独立任务。01 已完成配置支持实现；四技能当前值仅为临时验证样本。02 正依据[当前空间配置基线](../../../../Baseline/CharacterPresentation/02-SkillActionPresentation.md)反推并细化导出需求，03—04 保持粗略初稿，均尚未实施。01 的程序实现与证据见 [Batch04-01 程序工作流](../../../../ProgramWorkflow/CharacterPresentation/Batches/Batch04-OnDemandSpatialAdaptation/README.md)。

## 四项任务

| 文档 | 任务与交付 |
| --- | --- |
| [01 技能系统空间配置支持](01-SkillSpatialConfigurationSupport.md) | 在既有系统上补齐可复用空间能力，明确 C++ 机制、Lua 组合/计算、JSON 参数/绑定；四技能用于接入验证。 |
| [02 实际技能释放采集与导出工具](02-SpatialDataExportTools.md) | 脚本自动运行指定场景、角色与技能，导出本次实际配置、运行空间数据及 PNG 序列，无需手动 PIE。 |
| [03 空间数据读取](03-SpatialDataReading.md) | 独立读取 Agent 理解材料，留下可复用的结构化空间说明。 |
| [04 空间适配配置](04-SpatialAdaptationConfiguration.md) | 配置 Agent 消费说明，自主配置并观察、调整实际结果。 |

“反推需要什么数据”由策划在细化上述需求时完成，不另设第五项任务。先从 01 明确可配置内容，再据此细化 02、03，最后明确 04 的执行要求。01 可用指定测试参数独立验证；04 同时依赖 01 的配置能力、02 的观察工具和 03 的读取产物。

## 共用边界与依据

- 用户确认 Fireball（投射物）、AreaBurst（地面范围）、Mend（自疗）、BurningBuff（持续状态）的释放时点目前相对正常。这是有限样本观察，不等于全部表现通过；四技能用于参考和验证，不是能力白名单，不扩展玩法或重做释放时点。
- 空间资料按任务特化取得，先复用适用资料，不足才补查。不默认全骨骼、全帧或全顶点采集，不为每个动作预建完整空间报告。
- 查询/观察资料及读取说明先保存为结构化文本，与实际运行配置职责独立、可读取可追溯；不预定 schema 或文件布局。
- 允许适配真实投射物生成位置，同时检查相关轨迹、遮挡和近墙影响；不得擅改目标合法性、伤害、碰撞策略等规则。特效不裁定战斗结果，Gameplay Event 与 Gameplay Cue 不混淆，不预设迁移 Cue。
- 沿用 C++ 稳定通用能力、Lua 流程/条件/空间计算、JSON 高频参数的方向，不将所有位置或计算都固化为 JSON；不指定类、API 或 UE 资产内部结构。
- 不包括资源盘点、AI 自动筛选资源、正式美术制作、完整策划设计管线、ACT/FPS 或全项目改造。使用替代资源时说明限制，最终美术质量仍需独立验收。

各任务读取本入口和自己的正文，按需读取直接上游交付；共用语义参照[角色表现共享基线](../../../../Baseline/CharacterPresentation/README.md)及正文 01—03。当前实现与工具能力由程序侧核实，策划不从程序材料推断需求。

本批依据用户讨论及本次四任务拆分确认。Action 工作流仅借鉴“观察后留下注明变化、源帧/区间及幅度峰值的可消费说明”的经验，可参考 [Batch03 动作总览需求](../Batch03-MontageNotifyPlacement/AnimSequenceActionOverviewRequirements.md)第 3 节，不继承其批次范围或重跑成果；产物转换与职责划分参考 [AI Native 原则](../../../../../../../AI_NATIVE_GAME_DEV_PRINCIPLES.md)相关章节。
