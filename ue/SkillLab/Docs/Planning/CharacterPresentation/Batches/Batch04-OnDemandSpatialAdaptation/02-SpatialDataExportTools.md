# 02：实际技能释放采集与导出工具

## 1. 工具做什么

**状态：需求讨论稿，供用户审阅；下列命令、参数和文件约定是待实现要求，不是已有接口。**

提供一个脚本可调用的工具：指定场景、已配置角色和技能，自动运行一次真实释放，导出这次释放的配置、空间数据和同步画面。调用者无需手动开启 PIE、操纵角色或截图。它是对游戏实际行为的采集，不重新拼装动画预览或另做一套火球发射。

采集单元为“一个角色的一次指定技能请求及其产生的施法/对象”，涉及的 Skeletal Mesh、AnimBP、Montage、Notify、投射物或表现资源均从实际角色及有效配置读取。不分别要求调用者填写这些资源，不以四技能为白名单。其他角色的同类能力应可复用。

输入由后续工作流提供。工具不决定选哪个技能、关注哪个部位、是否需要补视角或怎样调整参数；[03 数据读取](03-SpatialDataReading.md)与 [04 适配配置](04-SpatialAdaptationConfiguration.md)分别决定观察与复查策略。[批次入口](README.md)维护四任务关系。

## 2. 调用方式与自动运行

要求提供统一 Python 命令行入口，建议落点为工作区 `tools/export_skill_spatial.py`。本需求固定以下调用行为，程序可根据已有入口确定内部桥接方式：

```text
python tools/export_skill_spatial.py inspect --request <请求JSON绝对路径>
python tools/export_skill_spatial.py capture --request <请求JSON绝对路径>
python tools/export_skill_spatial.py configure --output-root <绝对路径> --save-default
```

- `inspect`：加载指定场景及角色，读取技能目录、绑定、模型与可查询参照，导出查询结果；不请求施法。
- `capture`：加载指定场景及角色，按请求执行一次正式技能请求，采集数据和画面，保存后退出本次工具启动的 UE 进程。
- `configure`：保存默认输出根目录；默认作用于 SkillLab，可用 `--project <uproject绝对路径>` 指定其他项目。设置保存在对应项目 `Saved/SpatialExportTool/settings.json`，不修改运行技能配置。
- 一次请求处理一个施法者和一个技能。批量工作由多份请求逐个调用，不引入自动选技能或遍历全项目资源的策略。

脚本自动启动具备渲染能力的 UE 运行环境，加载项目、场景和原有角色组装/技能初始化流程。可复用已有导出的进程、渲染和保存设施；内部采用自动运行游戏场景或其他入口由程序验证，不强制 PIE，也不把连接手动运行的 PIE 作为必需前置。支持无窗口/离屏则说明条件；无法支持时允许显示自动运行窗口，不承诺所有机器均能离屏。

纯 NullRHI 数据运行不能充当画面采集完成。程序需交付从命令启动到结果落盘的端到端用法，不将找进程、启动场景、按键释放等操作留给用户。

## 3. 请求参数与角色定位

请求文件为 UTF-8 JSON。下列参数及语义作为外部调用约定；程序实现时需提供完整合法请求样例和校验说明。

| 参数 | 必需性/默认值 | 含义 |
| --- | --- | --- |
| `project_path` | 可省略 | `.uproject` 绝对路径；默认入口所属工作区的 `ue/SkillLab/SkillLab.uproject`，不得转到另一工程。 |
| `engine_executable` | 可省略 | UE 启动程序绝对路径；省略时复用项目已有引擎定位方式，无法定位即失败，不静默选任意引擎。 |
| `map` | 必填 | 要加载的关卡资产路径。场景须已有可用角色或沿原 GameMode 生成角色，不为导出自动更换 GameMode/角色类。 |
| `caster` | 必填 | 精确定位施法者：`player_index` 或 `level_actor_path` 二选一；前者取原有玩家生成的 Pawn，后者取当前关卡中对应 Actor。必须匹配一个有效技能拥有者。 |
| `skill_id` | capture 必填；inspect 可省略 | 已配置的技能标识。inspect 省略时列该角色已配置的技能及绑定，不枚举全工程资产。 |
| `target` | capture 按技能必需 | 单位目标传 `actor`，使用与 caster 同样的定位方式；地面目标传世界 `ground_location`（厘米）；自身技能省略，使用自身语义。不得替请求自动选一个敌人。 |
| `related_actor` | 可选 | 显式关联对象的精确定位；只有配置需要时提供，缺失不能用目标冒充。若既有执行入口无法传入，应明确报告不支持。 |
| `reference_queries` | 可选，默认空数组 | 每项明确 `source`（caster/target/related_actor）、`component_path`、`kind`（bone/socket）、`name`。可由 inspect 结果取得名称和组件路径。 |
| `warmup_seconds` | 默认 1，非负 | 场景和角色初始化后的预运行时间；仍须确认技能初始化完成，超过总超时未就绪即失败。 |
| `pre_request_seconds` | capture 默认 0.25，非负 | 开始记录后，等待该时长再提交技能请求，用于保留请求前画面。 |
| `duration_seconds` | capture 必填，正数 | 从技能请求提交起继续采集的秒数。到期正常结束采集，不强制提前结束仍存活的技能对象。 |
| `sample_hz` | capture 默认 30，正数 | 期望画面和周期空间采样频率；记录实际时间及漏采，不承诺请求频率就是实际实现精度。 |
| `views` | 默认 `[{"id":"game","type":"game"}]` | 视角对象数组，id 唯一。type=game 使用游戏相机；type=custom 必须提供 `location_cm`（X/Y/Z）、`rotation_deg`（Pitch/Yaw/Roll）、`fov_deg`（水平 FOV，0 到 180 度之间）。本轮只要求透视相机。 |
| `resolution` | 默认 `[1280,720]` | 每张图像像素宽高，均为正整数。 |
| `markers` | 默认 false | 是否额外输出带查询参照、名称和轴向的标记图；开启时保留对应无标记画面。 |
| `timeout_seconds` | 默认 120，正数 | 从启动至结果结束的最长墙钟时长；必须容纳初始化和请求的采集时长，超时报告当前阶段并收束本次进程。 |
| `output_root` | 可选 | 本次输出根目录绝对路径。优先于已保存的工具设置；两者均无时使用项目 `Saved/SpatialExports`。 |
| `parent_run_id` | 可选 | 补充采集所关联的旧结果编号；只建立关系，不保证重新运行与旧运行轨迹逐帧一致。 |

`level_actor_path` 是 Actor 在指定关卡中的明确对象路径，`component_path` 为该 Actor 下的明确组件路径。工具输出定位候选供调用者纠正，但不能名称模糊匹配后静默选第一个对象。动态生成角色本轮优先通过 `player_index` 定位；不要求在此工具中新增通用 NPC 生成系统。

默认查询数据包括角色、目标/关联对象（若有）、实际使用模型的变换、既有空间配置明确绑定的参照，以及本次生成对象。`reference_queries` 用于增加其他候选参照；为空不触发全骨骼逐帧导出。inspect 输出相关模型的可查询骨骼/Socket 名称及组件路径，供后续明确请求使用。

参数、目录和引用能在启动前检查的先检查；其余在运行后校验。技能尚未授予、目标不合法、资源不足、冷却中等按原技能规则拒绝，不通过无限资源、跳过门控、直接调用效果执行器等方式伪造成功。需要其他测试条件时由调用者准备相应场景。

例如下列请求表达“场景中 0 号玩家使用当前自疗技能，记录请求前 0.25 秒及请求后 3 秒，使用游戏视角，不另加骨骼查询”。关卡路径是待调用者填写的占位值，不声称以下请求已在当前工程验证：

```json
{
  "map": "<关卡资产路径>",
  "caster": {"player_index": 0},
  "skill_id": "Skill_Mend",
  "duration_seconds": 3,
  "pre_request_seconds": 0.25,
  "sample_hz": 30,
  "views": [{"id": "game", "type": "game"}],
  "resolution": [1280, 720],
  "reference_queries": []
}
```

单位目标的形态为 `"target":{"actor":{"level_actor_path":"<Actor对象路径>"}}`，地面目标的形态为 `"target":{"ground_location":[X,Y,Z]}`，三值为世界厘米坐标。reference_queries 的组件路径与名称应取自 inspect，不要求用户猜 UE 对象名。

## 4. 从哪里读取，怎样完成一次采集

### 读取实际状态

配置材料取自本次角色实际加载并使用的有效定义和运行绑定，同时记录可回查的源文件/资源身份。只解析磁盘 JSON/Lua 不能证明已生效；禁止为读取资料额外任意执行技能脚本或建立另一套空间解析规则。

实际角色提供模型、Skeleton、AnimBP/动画实例和组件身份；实际播放记录提供 Montage、播放位置、Section、速率、相关源动画及必要的混合条件。相关资源仅作为本次运行的依赖与来源记录，不另外导出一套独立资源观察任务，也不复制 UE 二进制资产。

### 自动执行顺序

1. 校验请求并建立独立输出目录，启动本次 UE 场景，按参数定位角色、目标与关联对象。
2. 等待原有初始化和指定 warmup 完成，记录实际配置/资源快照；inspect 在此生成查询资料并结束，不提交技能。
3. capture 开始记录请求前画面，然后通过原有正式请求入口提交一次技能，保存请求结果及对应施法身份。
4. 推进真实场景，按请求采样画面和空间状态；监听同次施法的释放、生成、效果及终态等已有事实，保留对象来源。Notify 仅是时机事实，不当作命中或成功。
5. 到达采集时长或发生不可继续的失败后，写完结果索引，返回实际路径及状态，关闭本次工具启动的进程。

技能自然完成不自动停止采集，继续观察到指定时长，以便看到独立飞行的投射物或持续效果。对象在结束时仍存活或未出现命中/移除事件，明确记录“截至本次采集结束尚未发生”，不伪造结束，也不据此单独判定技能失败。

## 5. 要记录的数据与画面

| 内容 | 必需信息 |
| --- | --- |
| 当前定义与绑定 | 技能、各被配置对象、事件、位置/方向来源、偏移空间和值、视觉修正/比例、一次放置或跟随方式；资源及模型绑定、加载快照线索与权威来源。 |
| 模型与动作 | 实际模型/骨架、组件、动画实例、Montage 播放记录与时刻；查询参照在该播放状态下的局部及世界变换。 |
| 技能与对象事件 | 本次请求及 Cast 身份、释放/实际生成时刻、实际对象与效果实例来源；实际生成位置、执行/飞行方向及适用后续状态。 |
| 视觉和几何参考 | 本次实际使用的 StaticMesh 本地包围范围、原点/轴向、视觉比例及运行承载的额外尺寸基准；投射物可见朝向、飞行方向与碰撞形状参考分开记录。 |
| 同步画面 | 每个指定视角的实际场景 PNG 序列，记录相机状态、画面编号、采样时间和关联空间样本；需要 markers 时另存标记图。 |

周期数据记录采样编号、模拟时间和相对请求时间。原始事件保留实际触发时间，生成点等数据尽量从真实执行时刻取得，不能用下一次定期采样冒充生成瞬间；无法同时取得的字段标明采样时间差和限制。

骨骼数据与画面必须有明确的姿势求值及画面采样对应关系。UE 事件、动画求值和渲染存在阶段差异时，应记录实际对应帧/时间差；不能只因写在同一 JSON 行就宣称严格同步。不另行播放一段 AnimSequence 来补“真实运行坐标”。

同次运行中的不同视角应关联同一模拟状态；做不到时须显式标记，不能把多次施法画面合称同一帧。附近障碍保留在场景画面中；工具不消除遮挡、穿墙或修改碰撞策略来改善结果。

当前支持范围遵循[空间配置基线](../../../../Baseline/CharacterPresentation/02-SkillActionPresentation.md)：表现资源限 StaticMesh，持续跟随限持续效果表现的施法者/目标来源，表现事件限已接入事件，另有真实投射物生成。不在本任务补 Niagara、任意事件演出、完整表面测量或全骨架/全顶点采集。

## 6. 保存位置、文件形式与读取入口

通过 configure 保存默认输出根目录，或按请求的 `output_root` 临时覆盖。临时覆盖不更改已保存默认值。不可写时失败，不静默改存其他目录。默认落点在当前工作区为 `E:/agent/game/ue/SkillLab/Saved/SpatialExports/`，属于生成产物，不是 Planning 需求或运行配置。

每次运行在根目录下创建唯一 `run_id` 子目录，建议编号由时间与随机后缀组成；不覆盖旧结果。文本 UTF-8，图像 PNG；不强制导出视频。以下文件角色与文件名作为交接约定：

```text
<output_root>/<run_id>/
  request.json          # 原请求与补齐后的实际参数
  manifest.json         # 读取入口、状态、对象身份、文件索引与缺失项
  configuration.json    # 实际加载的配置、模型/资源绑定、来源与版本线索
  references.json       # 模型组件及可查询参照；inspect 也提供
  events.jsonl          # 实际请求、释放、生成、效果、终态等事件
  samples.jsonl         # 时间采样、对象/参照变换、相机及画面对应关系
  frames/<view_id>/     # 无标记 PNG 序列
  marked/<view_id>/     # 可选，同编号标记图
  diagnostics.txt       # 错误/警告摘要
```

inspect 不生成事件、采样和图像序列，manifest 明确其模式及未生成文件；capture 无事件时也保留可读取的空事件文件。manifest 必须有 `schema_version`、`run_id`、模式、状态、实际参数引用、项目/关卡/角色/技能身份、起止时间、采集覆盖范围、文件相对路径、缺失/失败项和限制。configuration 等内部字段由程序设计并随工具交付字段说明，不允许缺失上文规定的语义。

结构化记录中使用稳定运行内标识关联 Actor、Cast、效果、事件和样本，不能只靠屏幕显示名或数字 CastId 跨运行关联。实际运行对象原名/路径可同时保留。位置采用厘米，角度若使用欧拉角须标明 Pitch/Yaw/Roll；四元数须声明分量顺序；局部变换必须能定位父参照。不得让读取 Agent 猜单位或变换空间。

画面文件名使用固定宽度采样编号，时间与样本关系以 manifest/samples 为准，不从文件名推测精确时刻。末尾标准输出返回一行机器可读 JSON：`run_id`、`status`、`output_dir`、`manifest_path`、`errors`。读取 Agent 从 manifest 开始，再按索引找配置、事件、样本和画面，不需要扫描源码或日志推断结果。

保存前冻结本次配置来源的可识别版本/内容指纹及资源身份；不能只写生成日期。旧资料是否适用由后续工作流判断，工具只提供足够线索。源资产/配置变更后补采建立新 run_id，可用 parent_run_id 关联，不能把两次运行拼成一个连续施法。

## 7. 失败反馈与验证

状态分为 `complete`、`partial`、`failed`：complete 表示指定技能已受理且约定采集完整，不表示命中、美术或技能功能验收通过；partial 表示请求已受理且已有可用材料，但部分查询/帧/视角缺失；failed 表示无法定位、请求被拒绝、采集关键链失败或没有可用画面。inspect 的 complete 表示指定查询完成，不要求施法受理。

退出码分别为 0、2、1。校验失败也应返回机器可读错误；能建立输出目录时落盘失败 manifest，目录不可写时至少在标准输出/错误输出说明原因。运行中超时或异常退出保留已有材料并标注阶段，不将部分结果报告为完整成功。

| 验收操作 | 预期结果 |
| --- | --- |
| 纯脚本查询 | 无需手动 PIE，inspect 定位指定角色，返回已配置技能/资源及模型参照；不触发技能或扫描全工程。 |
| 一次真实释放 | 使用完整请求执行 capture，自动初始化、正式施法、取帧和退出；画面、配置及事件属于同次实际施法。 |
| 指定目标 | 单位、地面、自身目标各选适用配置验证；缺少必需目标明确失败，不自动找目标或绕过正式门控。 |
| 输入控制 | 更换采样范围、查询参照或视角，结果随参数变化；无效角色/组件/参照、无权限目录和超时有明确状态。 |
| 数据与画面 | 实际 Montage 姿态与骨骼数据有对应采样线索；释放/生成瞬间数据有独立时间信息，飞行、视觉朝向和碰撞参考可区分。 |
| 后续过程 | 采集时长覆盖适用的一次生成或持续跟随；Cast 完成后仍可记录独立对象，结束时未发生事件标明未观察到。 |
| 文件交接 | 仅凭 stdout 的 manifest 路径，独立读取者可找到配置、空间数据和对应 PNG；重复执行不覆盖，版本和失败范围可辨。 |
| 通用复用 | 对另一个已支持内容/角色执行同类请求，不增加技能名专用分支。四技能是验收样本，不限制工具支持范围。 |

程序交付脚本入口、运行侧采集能力、请求样例、参数/数据说明和可复现验证结果。C++ 负责必要的真实运行查询、事件关联与渲染采集接入，Python 编排进程、请求与文件结果；复用既有技能和空间运行能力，不建立第二套生成/求值规则。内部类、接口和 UE 启动参数由程序决定。

本任务不要求独立 StaticMesh 资源分析器或纯 Montage 预览导出器；当前对象属性随本次技能运行读取。是否选择观察某次释放、怎样读图和怎样给出配置建议留给 03/04，不作为工具内部判断或验收条件。基线未充分验证的生产 Socket、释放前移动后采样和近墙情境仍需取得证据，导出工具不预先宣布它们已通过。
