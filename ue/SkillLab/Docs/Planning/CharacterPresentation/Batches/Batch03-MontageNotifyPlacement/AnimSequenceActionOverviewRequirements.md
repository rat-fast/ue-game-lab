# AnimSequence 动作总览需求

## 1. 目标

为 AI、策划和美术提供可复查的动作观察材料。输入任意兼容的 UE `AnimSequence`，自动逐帧播放并渲染角色，按帧号和时间码生成一张或多张分页总览图，同时输出机器可读的 `manifest`。

该能力解决“AI 如何高效、可靠地理解动作”的前置问题。它不负责决定 Notify，不负责技能逻辑，不负责修改 Montage，也不宣称动作总览本身已经完成游戏内表现验收。

## 2. 适用范围与职责

### 适用范围

- 面向任意满足程序侧兼容条件的 `AnimSequence`；不绑定某个技能或四个测试技能。
- 支持批量处理资产，并为每个资产产出可追溯的图像和结构化索引。
- 允许后续 Notify 配置、动作审核或其他内容流程消费同一份观察结果。

### 不负责的内容

- 不写入或修改 Notify。
- 不判断技能需要几个事件，不决定攻击、发射、伤害或成功规则。
- 不替代动作资源选择、美术制作、Montage 编排或游戏运行时验证。
- 不把总览图中的可见变化直接当作业务事实。

## 3. 面向使用者的产物

### 输出位置

总览图和 `manifest` 必须自动保存为本地产物。生成器应允许用户配置一个输出根路径，并持久保存该配置；配置完成后，后续生成默认持续使用该路径，不要求每次手动选择保存位置。

同一输出根路径下，应按输入资产和本次生成建立可区分的子目录。重复生成不能静默覆盖已有结果；具体目录命名、版本标识和清理策略由程序侧设计，但必须能从结果回溯到输入资产和生成批次。生成完成后应返回实际输出路径，供后续 Agent 读取。

若已配置路径不可用、无写入权限或产物生成不完整，应明确报告失败，不得静默切换到另一个路径后宣称成功。是否允许本次临时覆盖默认路径作为高级选项，由程序侧评估，不改变“默认使用已保存路径”的规则。

### 总览图

总览图应按固定规则排列动作帧，支持一张或多张分页图。每个格子至少显示帧号和时间码，并能从页码、格子位置回到原始帧。分页范围应清楚，长动作不能因缩小到无法辨认而失去观察价值。

总览应尽量使用稳定的预览条件：固定相机、画面尺寸、角色比例、地面或空间参照。默认视角和是否提供侧视、正视或其他视角需要程序侧评估；不能让相机随动作自动变化而掩盖姿态差异。

骨骼线、Socket、武器挂点、轨迹和 Root Motion 等辅助层可作为可选观察信息。默认不应遮挡角色主体；显示哪些辅助层、如何标注名称和如何与结构化数据对应，需要结合使用场景确定。

### manifest

`manifest` 至少应记录：

- 输入资产身份和路径；
- Skeleton、预览 Skeletal Mesh 及其来源；
- 帧率、总帧数、总时长和帧号/时间码规则；
- 分页数量、每页帧范围、每个帧号对应的图片页和格子；
- 使用的相机和渲染条件；
- Root Motion 是否存在及其可核对的范围；
- 可选骨骼、Socket 或轨迹辅助信息的名称和对应关系；
- 生成时间、版本或其他足以复查产物的标识。
- 输出根路径和本次实际产物目录，或可由 `manifest` 稳定解析到它们的引用。

最终字段和格式由程序侧设计，但必须足以让后续流程确认“看的是哪个资产、哪一帧、哪一页、哪一个预览条件”。

### 动作语义结果

AI 读取总览图和 `manifest` 后，可输出独立、可复查的动作语义结果，包括：

- 前摇、蓄力、出手、接触、释放、回弹、收势等阶段及其帧/时间范围；
- 与技能或表现需求有关的候选时点；
- 每个判断使用的可观察依据；
- 多个候选点、动作不清晰、资源不匹配或语义冲突；
- 需要人工取舍的问题和未确认项。

该结果供本批 Notify 配置正文或其他内容流程消费；不能只存在于一次性对话中。语义结果不直接等于 Notify 已配置，也不等于技能业务已经发生。

## 4. 能确定什么，不能确定什么

### 总览可以支持

- 识别动作的大致阶段和顺序；
- 比较前后帧，定位明显的出手、接触、落地、回弹等可观察变化；
- 观察多次动作的相对间隔；
- 发现动作无法承载预期事件或存在明显歧义。

### 总览不能单独证明

- Notify 已写入实际运行内容；
- Montage、Section、播放速率、Blend 或其他运行条件没有改变时序；
- Socket 在运行时的精确变换；
- 通知已经被正式运行入口触发并被技能逻辑受理；
- 技能是否取消、是否允许执行、是否命中、是否造成伤害或发射；
- 玩家在游戏内最终看到的事件时序已经通过验收。

这些结论需要结构化回读、程序核实和游戏内运行验证。

## 5. 给程序侧的最小能力需求

| 能力 | 要求的结果 |
| --- | --- |
| AnimSequence 读取 | 明确兼容范围，能定位实际输入资产并取得帧率、时长、Skeleton 等基础信息。 |
| 逐帧渲染 | 按源动画帧生成稳定、可复查的角色图像，不因逐帧失败静默跳帧。 |
| 分页与标注 | 生成可阅读的分页总览，保留帧号、时间码、页码和格子映射。 |
| 预览条件 | 记录并复用预览 Skeletal Mesh、相机、比例和必要的渲染条件。 |
| 辅助信息 | 能核对 Root Motion，并评估骨骼、Socket、轨迹等辅助层的提供方式。 |
| manifest | 输出资产、帧、分页、图像映射和预览条件等机器可读信息，可供后续流程读取。 |
| 输出路径配置 | 允许配置并持久保存输出根路径；后续生成默认使用该路径，产物按资产和生成批次区分，失败时明确报告。 |
| 可追溯生成 | 重新生成时能区分资产、版本和产物，发现输入变化或生成失败。 |
| 交接映射 | 能让后续流程把 AnimSequence 帧/时间对应到实际使用的 Montage 或其他播放内容；具体映射能力待核实。 |

本文不指定 C++、Blueprint、Lua、MCP、文件格式或内部资产拓扑。程序侧应报告无法兼容的资产、预览条件缺失、渲染失败和映射不完整，不以生成了图片就宣称动作观察能力通过。

## 6. 失败与歧义处理

- 输入资产不兼容、缺少 Skeleton 或预览 Mesh：报告资产身份和缺失项，不生成无法解释的伪总览。
- 某些帧渲染失败或分页不完整：标记具体帧和页，不能静默补帧或把不完整结果当作完整输入。
- 相机、角色比例或 Root Motion 参照不稳定：标记影响范围，不能把跨条件的图像直接比较。
- 图像可见动作与结构化时间关系不一致：以可复查的映射为准定位问题，暂停下游语义消费。
- 动作存在多个合理阶段或无法判断事件：输出候选及依据，交由后续内容负责人取舍，不替 Notify 流程静默选定业务语义。

## 7. 验收要求

| 场景 | 预期结果 |
| --- | --- |
| 单资产总览 | 对兼容 `AnimSequence` 生成完整逐帧分页图和 `manifest`，能从任意帧号找到图片页与格子。 |
| 持久输出路径 | 首次配置输出根路径后，后续生成自动写入该路径；结果包含实际输出目录，重复生成不会静默覆盖既有产物。 |
| 批量处理 | 处理多个不绑定技能的资产，每项产物身份清楚，互不覆盖且可独立复查。 |
| 时间映射 | 帧号、时间码、帧率、总时长和分页范围互相一致。 |
| 预览一致性 | 预览 Mesh、相机和画面参照被记录，重新生成或复查时条件可识别。 |
| 辅助层 | 已启用的 Root Motion、骨骼或 Socket 信息能与对应帧和结构化记录关联；未启用时明确标记。 |
| 语义交接 | AI 能基于总览和 manifest 输出阶段、候选时点及不确定性，结果可供后续流程读取。 |
| 边界验证 | 总览生成器没有写 Notify、修改技能或把图像观察结果宣称为运行时业务结果。 |
| 失败可见 | 输入、渲染、分页、映射或预览条件失败时，能报告失败范围，不能静默通过。 |

总览生成通过不等于 Notify 配置通过。本批 Notify 配置正文仍需独立完成 Notify 写入、保存/重载、回读和游戏内时序验证。

## 8. 程序侧待核实项

- 当前可批量读取和渲染的 `AnimSequence` 范围，以及实际可用的预览 Skeletal Mesh 来源。
- 逐帧渲染、稳定相机、分页和标注的可行能力及证据形式。
- Root Motion、骨骼、Socket 和轨迹信息的可读性与是否需要单独结构化输出。
- `AnimSequence` 与实际 Montage、Section、播放条件的映射能否可靠建立。
- 生成产物如何被 AI 和本批 Notify 配置流程读取、回查和识别版本。
- 当前缺失预览资源、渲染失败、资产不兼容和批量处理失败时可提供的降级边界。
- 输出根路径配置的保存范围、不可用路径的报错方式、重复生成的版本和清理策略。

以上是程序需要核实的事实和能力，不是对当前实现的判断，也不指定程序架构或任务拆分。

## 9. 已确定与待确认

### 已确定

- 这是本批内独立于 Notify 配置的通用动作观察功能。
- 输入是任意兼容的 `AnimSequence`，不是某个技能专属资产。
- 输出包括逐帧分页总览图和机器可读的 `manifest`。
- 输出根路径可配置并持久保存，后续生成默认持续写入该路径；结果按资产和生成批次区分。
- 总览生成器不写 Notify、不决定技能事件、不替代运行时验证。
- 四个技能可以作为首次测试样本，但不是工具范围限制。

### 待用户与总控讨论

- 任务派发者、专用 Skill / Agent、上下文边界和与本批 Notify 配置的交接顺序。
- 分页密度、默认相机、是否生成额外视角、辅助层默认开关。
- 动作语义结果的正式载体，以及 AnimSequence 到 Montage 的映射要求。
