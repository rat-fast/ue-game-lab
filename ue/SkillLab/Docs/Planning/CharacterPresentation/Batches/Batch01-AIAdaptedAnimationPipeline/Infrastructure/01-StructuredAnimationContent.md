# 01：结构化动画内容

## 目的

让可变动画内容拥有稳定的生产入口，使人和 AI 能理解内容、定位条目、提出局部修改、回读修改结果并验证引用与规则。

## 当前共享基线依赖

当前表现基线能定位基础动画与四个技能的动作路径，但没有确认默认绑定、资源内部内容、Skeleton 一致性或运行结果。基线只说明存在的证据，不构成配置规范。

## 本批策划承诺

- 动画内容需要有结构化且语义明确的入口，能够描述并定位可变内容及其资源关联。
- 修改操作应能限定到目标内容，修改后可回读并识别实际变化；不能要求内容生产者只能通过任意源码编辑或模拟编辑器鼠标操作完成日常修改。
- 对资源缺失、引用无效、兼容性不符和不支持的字段，应能给出可定位的校验结果。
- 内容入口服务于同一领域语义的人类和机器操作；文本、图形界面、结构化 Patch、工具 API 均是候选形态，不预设其一。

## 建议实现方向

先由程序架构从现有产物和实际职责中归纳稳定领域概念，再决定机器接口与 UE 资产/运行后端的映射。可读/可 diff 的结构化表示可作为候选，但不意味着必须建立 JSON、特定 Schema 或全量取代 UE 编辑器。

## 当前限制

- 尚无经核对的内容模型、权威资源引用规则或可回读的生产工具。
- 配置路径本身不等于策划权威；策划确认的内容语义应与运行时承载形式分层。

## 验收条件

- 可从生产入口定位到某项动画内容和其资源依赖，并能读取其领域含义。
- 对一个内容项做局部修改后，能够重新读取权威结果，明确显示变更，并按约定回滚或重做。
- 对无效引用、缺失内容和不兼容资源至少能报告具体条目及原因；校验结果可被自动检查。
- 人工通过既定编辑入口和机器通过既定接口处理同一内容时，语义一致，结果可 Review。

## 明确排除项

不冻结 JSON 示例、Schema、数据字段、命名约定、专用编辑器、资产创建工具或资产的最终组织结构。
