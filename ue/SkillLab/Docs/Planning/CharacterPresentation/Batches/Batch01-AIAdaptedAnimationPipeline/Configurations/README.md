# 具体表现配置

## 状态：配置暂缓

当前不建立火球、区域爆发、修复或燃烧效果的正式具体表现配置。共享表现基线与技能系统基线足以确认四者的业务差异和运行事实类型，但不足以确认权威动作选择、动画释放时点、资源内部结构、兼容性或降级体验。

当前 `Config/SkillDefinitions.json` 中的动作路径只是实现/代码文档记录的现状引用；基线明确未证明路径可解析、资源可播放、内部 Skeleton/Notify/Slot 内容或与释放事实对齐。路径不会自动成为策划权威配置。未提交动画实验也不作为已验证资源或规则。

共享技能基线已经确认四项技能的业务差异：火球是敌方单位目标的投射物伤害；区域爆发是地面位置范围伤害；修复是对自身立即治疗；燃烧效果是对敌方单位施加持续伤害。未来的具体表现配置须保留这些差异，但目前没有证据据此选择动作、释放帧或资源。

## 建立配置的前置条件

1. 程序完成本批生产入口和回读/校验能力的架构及实现评估，并明确策划能配置的领域内容。
2. 资源经目标 UE 版本核对，至少确认资源身份、Skeleton/兼容关系、动作/片段内容及必要的 Montage 结构能够回读。
3. 在 UE 运行中取得技能运行事件与可见动作的可复现证据，能定位动作开始、释放/效果、取消、完成和基础姿势恢复之间的关系。
4. 用户或策划确认每项技能所需动作体验、缺少资源时的降级反馈，以及持续效果与施法动作的边界。

## 配置进入方式

满足前置条件后，由具体技能表现需求逐项建立权威配置文档，覆盖动作资源选择、动作与释放阶段的关系、取消/完成后的表现、基础姿势恢复、资源缺失降级体验和技能间差异。具体参数以已确认资源和运行证据为依据，并引用相应的共享基线和本批公共需求。

程序实现中的 JSON、UE 资产路径或工具生成文件可作为实现/验证证据，但不因其可运行或可读取而自动成为策划权威来源。配置文档不得重复公共程序需求。

## 待用户确认

- 缺少技能动作资源时，期望采用何种最低可接受反馈？在得到确认前不指定默认动作、静默处理或占位动画。
- Cast 完成/取消后，如果技能效果仍独立持续，是否要求角色立即恢复基础姿势？此项在 Batch01 入口列为待确认，本配置入口不替用户决定。
