# Lua 技能组合与内容配置试点需求

## 1. 目标与玩家结果

本批把当前已有的 `Skill_Fireball`、`Skill_AreaBurst`、`Skill_Mend`、`Skill_BurningBuff` 接入 Lua 组合层和 JSON 内容配置层。目标是让技能的可变流程组合和可调整内容更易维护，同时保留 C++/GAS 稳定底座的权威门控、结算和清理职责。

玩家不应因技能由 Lua 组合而看到不同的业务行为。相同技能、相同 JSON 内容版本、相同输入和相同初始状态下，Lua 路径与现有原生路径必须保持以下结果一致：请求是否被接受、目标与目标关系、阶段顺序、资源与冷却结果、命中与实际效果、持续状态、取消/完成终态、Reset 后状态和可观察反馈。内容版本经批准后可以改变相应可调内容，但同一版本不得出现重复结算或不确定结果。

开发者应能区分“组合或内容调整”与“稳定公共规则”，并能定位脚本失败、JSON 缺失/无效和表现资源缺失。具体编辑工具、脚本运行时和数据校验技术不由本需求规定。

## 2. 范围、依据与不变项

### 本批范围

四个现有技能都要具备 Lua 组合层和 JSON 内容配置接入目标：

| 技能 | 共享基线已确认的当前事实 | 本批迁移目标 |
|---|---|---|
| `Skill_Fireball` | 目标为敌方单位；执行方式为投射物；命中或被阻挡后结算伤害，未命中报告失败原因 | 用 Lua 表达投射物技能的阶段/动作组合与已批准的内容选项；JSON 承载可调整的技能内容，不改变目标、命中和伤害权威性 |
| `Skill_AreaBurst` | 目标为地面位置；查询范围内敌方单位；可同时影响多个目标；范围为空报告空区域 | 用 Lua 表达地面落点到范围执行的组合；JSON 承载范围和效果等经批准内容，不改变查询、去重和实际伤害结算 |
| `Skill_Mend` | 目标为自身；执行方式为即时目标；效果为治疗 | 用 Lua 表达自身目标到即时治疗的组合；JSON 承载经批准的内容，不把名义治疗意图当成实际治疗结果 |
| `Skill_BurningBuff` | 目标为敌方单位；即时施加持续伤害；当前基线明确持续四秒、每秒一次，并在结束或清理时报告移除 | 用 Lua 表达施加持续效果的组合；JSON 承载经批准的持续内容，不改变周期结果、效果身份和移除事实 |

### 明确不带入本批

Batch01 的 `Firebolt`、`ArcStrike`、`BurnField`、`ChannelBeam`、`Barrier` 不作为本批迁移对象、验收对象或公共能力承诺。它们只可作为未来批次的候选范围，不得让本批需求、矩阵或实现默认覆盖六技能。

### 依据与不改变项

- 共享基线是四技能当前业务事实的主要依据；基线未给出的数值不在本需求中虚构。
- 既有请求、施法阶段、目标确认、命中/效果、持续状态、取消/完成、反馈和 Reset 语义继续有效。
- 本批只增加 Lua 组合和 JSON 内容维护目标，不重新定义四技能玩法，不新增效果类别，不改变玩家输入或槽位规则。
- 若现有基线与后续程序事实或历史策划建议冲突，先列为待核实/待确认，不自行选择一方改写产品规则。

## 3. 三层职责边界

| 层次 | 业务职责 | 禁止越过的边界 |
|---|---|---|
| C++/GAS 稳定运行底座 | 权威受理/拒绝请求；确认施法者、技能资格和目标；执行资源与冷却；产生施法身份和阶段；完成命中、实际伤害/治疗、持续伤害、属性修改、取消/完成、持续状态清理和 Reset；发布真实运行事实 | 不因 Lua 意图、JSON 值或表现回调而接受伪造命中、伤害、治疗、扣费、持续状态或终态；必须保持当前技能业务规则 |
| Lua 组合层 | 按技能内容表达阶段之间的组合、顺序、条件和已声明动作请求；消费真实请求/阶段/目标/效果事实；支持四技能的差异化流程维护 | 不能代替门控、目标最终校验、资源/冷却执行、命中判定、实际效果、持续状态所有权或 Cast/Reset 终态；不能从动画、特效或自身返回值伪造业务成功 |
| JSON 内容配置层 | 承载四技能经批准的可调整内容、技能身份和组合选项；让内容可审阅、可识别、可校验并与策划事实对应 | 不能成为 C++/GAS 公共规则的第二权威；缺失/无效内容不得静默当作零值、任意默认值或其他技能内容；本需求不规定 JSON schema 或字段格式 |

Lua 只表达流程组合并请求底座已声明的动作；底座是否已经提供足够的权威事件和动作能力，交程序侧核实。

## 4. 四技能可变内容与必须保持的行为

下表只定义内容维护目标和外部不变量。具体数值只有共享基线明确的内容才可写入当前需求；其他项目须由策划/基线确认后再进入 JSON 对照版本。

| 技能 | 适合迁入 Lua/JSON 的内容维护目标 | 必须保持的外部行为 |
|---|---|---|
| `Skill_Fireball` | 投射物技能的阶段组合、发射与命中后的已声明效果顺序；经批准的资源、冷却、阶段、投射物和伤害内容 | 目标保持敌方单位；投射物命中或被阻挡才结算；未命中仍报告失败原因；实际伤害只由权威效果结算；一次施法不能重复命中、扣费或终态 |
| `Skill_AreaBurst` | 地面确认、范围查询和多目标效果的组合；经批准的范围、阶段、资源/冷却和伤害内容 | 地面位置必须有效并通过正式检查；只影响范围内合法敌方单位；多目标结果可分别观察；空区域报告空区域而不伪造命中；实际伤害由底座产生 |
| `Skill_Mend` | 自身目标到即时治疗的流程组合；经批准的治疗内容、阶段和资源/冷却内容 | 目标固定为施法者；治疗受生命上限约束；实际治疗与名义治疗/无变化区分；满血不能被脚本伪装成实际恢复；重复回调不能重复治疗 |
| `Skill_BurningBuff` | 敌方单位目标到持续效果添加的组合；经批准的持续时间、周期、伤害和阶段内容 | 目标必须是合法敌方单位；当前确认的四秒持续时间、每秒一次周期事实须保持，除非另有产品确认；周期伤害、效果添加和移除分别可观察；持续效果身份独立于原施法并按规则清理 |

“可调整”不等于“已确认数值”。任何改变目标关系、实际结算、持续状态所有权、终态或 Reset 的内容，必须作为技能业务规则变更另行确认。

## 5. 请求、阶段、目标、效果、终态和身份兼容

1. **请求**：开始前拒绝不生成正式施法、不扣资源、不启动冷却、不施加效果。Lua 预览、条件分支或 JSON 读取成功不等于请求已被接受。
2. **阶段**：沿用当前技能已有的前摇、主动/执行、恢复和终态语义。阶段推进必须属于当前施法；旧回调、重复回调和脚本重入不能推进新施法。
3. **目标**：沿用自身、单位和地面目标形状、敌我关系、目标快照以及释放/效果前重检。目标候选、预览或脚本条件成立不等于真实命中。
4. **资源与冷却**：由 C++/GAS 底座按当前业务规则执行。Lua 重试、异步重入、内容重载或失败恢复不能额外扣费、重复启动冷却或退款。
5. **效果**：伤害、治疗和持续伤害必须读取权威实际结果、目标、请求量/实际量和结果状态。脚本意图、特效播放和命中动画不能替代效果事实。
6. **持续状态**：BurningBuff 的持续效果拥有独立身份和生命周期；周期、移除、目标失效、Reset 等结果由底座产生。Cast 完成不代表持续效果已经结束。
7. **取消/完成**：保持 `Rejected`、`Cancelled`、`Completed` 及技能已有无命中/失败结果的区分。每个 Request、Cast、执行对象和效果只能有一个终态；已发生的即时效果不因脚本或表现失败回滚。
8. **身份关联**：RequestId、CastId 以及适用的执行对象/效果身份必须能关联请求、阶段、目标、结果和清理。重载或新请求不能复用旧运行身份；具体身份是否可提供由程序侧核实。
9. **反馈**：HUD、日志、世界反馈和角色表现只显示权威拒绝原因、阶段、命中、实际效果、持续状态和终态。缺少反馈不能改变技能结果。

## 6. 与角色表现 Lua 试点的边界

- 两个 Lua 试点只通过真实技能事实连接：请求结果、阶段、目标、命中、实际效果、持续状态和终态可供表现消费。
- 角色表现 Lua 不能创建或改变请求、命中、伤害、治疗、资源扣除、持续状态或终态；技能组合 Lua 也不能根据动画、特效或表现回调宣告业务成功。
- 表现资源缺失、延迟或重复时，技能逻辑仍按底座继续或结束；表现可采用占位/简化反馈，但不能补发业务结果。
- 若权威事件不足以支持某项表现或组合，列为程序能力缺口，不由表现层合成事实。

关联入口：[Batch02 Lua 角色表现试点](../../../CharacterPresentation/Batches/Batch02-LuaCharacterPresentationPilot/README.md)。本需求不复制其动作和资源制作细节。

## 7. 失败与玩家可观察降级

| 失败情形 | 玩家可观察结果 | 必须保持的业务边界 |
|---|---|---|
| Lua 加载/执行失败 | 当前技能显示明确失败或不可用；已发生的权威效果保留；不得无期限卡住 | 不伪造命中、效果、扣费或终态；不影响其他技能和后续新请求；可定位技能与 Request/Cast（若已建立）及阶段 |
| JSON 内容缺失/无效 | 该技能不能开始，显示明确不可用/拒绝反馈 | 不静默使用零值、任意默认值或其他技能内容；其他三个技能继续隔离运行；可定位校验原因 |
| 表现资源不可用 | 逻辑、实际数值、持续状态和终态照常；使用占位/简化反馈或明确无表现 | 不因表现缺失中断逻辑；资源恢复不补发命中、效果、扣费或终态 |
| 运行中组合异常 | 停止尚未完成的组合动作并执行该技能既有清理；已结算结果保留 | 不重复费用/效果/终态，不遗留持续效果、预览或表现，不串扰其他 Cast |

脚本失败发生在请求前、施法中或权威效果提交后的具体对外文案和终态映射，列为程序/产品待确认，不在本需求虚构。

## 8. 明确排除项与待确认问题

### 排除项

- 不移除或重定义 C++/GAS 稳定底座，不规定类、组件、Blueprint 拓扑、Lua API、插件或迁移步骤。
- 不扩展 Batch01 六技能；`Firebolt`、`ArcStrike`、`BurnField`、`ChannelBeam`、`Barrier` 仅为未来范围。
- 不新增技能、效果类别、目标关系、玩家自定义技能、网络多人、存档/回放兼容或运行时任意脚本修改。
- 不规定 JSON schema、字段命名、编辑器、热更新机制或脚本安全策略。
- 不把策划需求、JSON 草案、脚本返回值或文档矩阵当作实现或运行验证证据。

### 待用户/策划确认

- 四技能中哪些未在共享基线明确的数值和阶段参数，应在迁移验收前冻结为原生/Lua 对照版本？
- 脚本失败时，玩家反馈范围是“单个技能暂不可用”还是“整套 Lua 试点暂不可用”？
- JSON 内容版本的批准、回退和变更记录是否需要产品规则；本批暂不默认热更新。
- 四技能是否都要求在同一轮完成可玩迁移，还是允许先完成一个纵向样本再扩展；本需求覆盖四技能，但不宣称实施已完成。

## 9. 程序侧待核实项

策划 Agent 不回答以下问题，程序 PM 需在允许的程序上下文中核实：

- C++/GAS/Skill runtime 是否能提供四技能所需的权威请求、阶段、目标、投射物/范围/即时执行、命中、实际效果、持续周期、移除、取消、完成和 Reset 事件？
- 这些事件是否带有可靠 RequestId、CastId、目标、原因、实际数值和先后关系，足以让 Lua 组合依赖真实事实？
- Lua 是否只能请求已声明动作，而不能绕过请求门控、目标校验、资源/冷却、效果结算、持续状态和终态？
- JSON 缺失/无效能否在技能开始前被识别并隔离单个技能？脚本运行失败发生在不同阶段时，现有生命周期如何清理和保留已提交结果？
- 重复事件、异步回调、内容重载、Reset 和连续施法的身份隔离与幂等性是否可验证？
- 角色表现 Lua 是否只消费真实技能事实；是否存在把表现事件误当成命中或效果事件的路径？
- 是否有可执行入口采集四技能原生/Lua 对照、内容隔离和脚本失败隔离所需的证据？

## 10. 功能验收矩阵

验收以四技能当前确认事实和另行冻结的内容版本为基准；同一输入、同一初始状态、同一 JSON 内容版本下比较原生与 Lua 路径。未运行项目标为“待验证”，不以文档、脚本返回值或实现摘要代替证据。

| 编号 | 范围 | 场景 | 通过条件 |
|---|---|---|---|
| L01 | 四技能覆盖 | 分别执行 Fireball、AreaBurst、Mend、BurningBuff 的基本成功路径 | 四项都能进入各自正确的目标/执行/效果流程；不把六技能当作本批通过项 |
| L02 | 原生/Lua 对照 | 同一技能、同一 JSON 内容、同一输入和初始状态分别走原生与 Lua | 请求结果、目标、阶段、资源/冷却、命中、实际效果、持续状态、终态和反馈一致 |
| L03 | Fireball | 敌方目标命中、被阻挡、未命中/到期、重复命中回调 | 只由真实投射物结果产生伤害；失败原因可区分；不重复伤害、扣费或终态 |
| L04 | AreaBurst | 有效地面位置、多敌方目标、空区域、无效位置 | 只影响合法范围内敌方单位；多目标结果独立可观察；空区域不伪造命中；无效位置不产生效果 |
| L05 | Mend | 自身有效治疗、满生命、释放前目标/施法状态失效、重复回调 | 只对自身生效；实际治疗受上限约束；满生命可区分 NoChange/无实际变化；不重复治疗 |
| L06 | BurningBuff | 合法敌方施加、四秒内每秒周期、自然结束、主动清理/Reset | 持续效果独立于原施法；当前四秒、每秒一次事实保持；周期、添加、移除结果和身份可追踪 |
| L07 | 内容隔离 | 让一个技能 JSON 缺失或无效，同时使用另外三个技能 | 坏技能明确不可用且不伪成功；其他技能行为不受影响；问题可定位 |
| L08 | 脚本失败隔离 | 在请求前、阶段中、执行中和效果已提交后模拟 Lua 失败 | 不伪造业务事实；已发生结果按规则保留；当前技能清理明确；其他技能、新 Cast 和旧身份不串扰 |
| L09 | 资源与终态 | 资源不足、冷却中、阻塞、目标非法、取消、死亡和 Reset | C++/GAS 按既有规则门控和清理；Lua/表现不能绕过或补造；终态唯一，Reset 后新运行使用新身份 |
| L10 | 内容调整 | 修改一个已批准的 JSON 可调内容项 | 只有对应内容结果变化；目标关系、门控、真实效果、持续状态所有权和终态不被意外改变 |
| L11 | 表现降级 | 缺失技能动作、命中特效或状态反馈资源 | 逻辑和实际结果仍正确；采用占位/简化反馈或无表现；资源恢复不补发业务事件 |
| L12 | 身份与重复 | 快速重复请求、异步旧回调、重载后回调、重复终止 | Request/Cast/效果身份不串号；每个业务结果和终态只发生一次；旧身份不能推进新运行 |

六技能 `Firebolt`、`ArcStrike`、`BurnField`、`ChannelBeam`、`Barrier` 的迁移对照和验收矩阵属于未来批次，不得用来宣称本批完成。

## 11. 当前确定、待定与未验证

- **已确定**：四个现有技能全部纳入 Lua 组合层/JSON 内容配置试点；C++/GAS 保留请求门控、目标校验、资源/冷却执行、真实效果、持续状态、终态和 Reset 权威；Lua 只表达流程组合并请求已声明动作；同内容版本下原生/Lua 外部行为一致；表现不能伪造技能事实。

- **未验证**：Lua/GAS 权威事件与动作能力、JSON 校验和隔离、脚本失败清理、身份幂等性、角色表现连接及全部验收矩阵场景。
