# 02：输入意图与统一请求

## 目的

本文定义物理输入、AI/Test 调用如何形成统一的技能业务请求，以及预览、确认、取消和持续会话的公共语义。本文不决定按键绑定、Widget、Enhanced Input 接法或 UI 资产。

## 统一链路

```text
物理输入 / AI / Test
→ 逻辑动作
→ 槽位解析与 SkillId 捕获
→ 操作意图与目标预览
→ 确认或取消
→ SkillRequest
→ 激活门控与技能生命周期
```

Player、AI、Test 可以有不同入口，但从提交 `SkillRequest` 起必须使用相同的目标、门控、效果和终止规则。来源只用于追踪，不改变业务结果。

## 固定公共语义

- 槽位解析只在开始形成意图时捕获 SkillId；换装不能重定向已确认意图、已提交请求或已开始会话。
- 操作意图不是施法实例，不扣资源、不启动冷却、不产生正式效果。
- 预览只显示候选合法性、范围、方向或位置；确认和正式执行必须再次检查。
- 预览取消、失焦、被控单位切换或目标上下文失效清理未提交意图，不产生正式请求副作用。
- 请求至少表达来源、施法单位、SkillId、目标规格、目标快照和追踪身份；拒绝请求也保留可读结果。
- 请求结果必须区分未开始的 `Rejected`、已开始的 `Started`、正常结束 `Completed`、主动取消 `Cancelled` 和被动中断 `Interrupted`。

## 支持的意图类型

| 意图 | 使用技能 | 需要的公共能力 |
|---|---|---|
| UnitTarget | Firebolt、Mend、Barrier | 单位选择、关系和最终重检 |
| GroundTarget | BurnField | 地面落点、位置快照和生成重检 |
| DirectionTarget | ArcStrike、ChannelBeam | 方向快照、方向预览和空间查询 |
| HeldSession | ChannelBeam | 开始、维持、停止、失焦和重复终止 |

技能文档决定某技能采用哪种意图；本文只保证这些意图能进入同一请求链。

## ChannelBeam 会话

开始时捕获 SkillId、CastId 和方向。后续松开、移动命令、失焦、死亡、Reset 或显式停止只能结束这一个会话；不能重新读取当前槽位而调用新技能。重复停止只发布一次终态。AI/Test 直接发送等价的 Begin/Stop 业务动作。

## 输入层不负责

输入层不判断最终资源、冷却、命中、伤害、治疗、护盾、状态清理或表现终态；它只形成意图、请求和会话动作，并显示公共结果。

## 公共验收入口

至少验证：四类意图都能形成正确请求；预览取消无 Cast/资源/效果；Player/AI/Test 结果一致；换装不改写旧请求；ChannelBeam 的松开、失焦和重复停止只结束原会话一次；右键取消与移动/镜头输入不会重复消费同一业务动作。
