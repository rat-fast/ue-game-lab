# 技能配置生产需求

## 目标与范围

面向当前技能系统建立技能内容的表达和维护边界，使技能专属定义不硬编码在 C++，且保持既有技能行为。内容生产方向不以四技能为上限；Fireball、AreaBurst、Mend、BurningBuff 是已知代表性样本。需要实际迁移的技能及数量尚未确定，由程序 PM 在现状核实与任务拆分后提出。Batch01 六技能新增内容迁移和玩法扩展不列为本轮要求。

## 内容表达

- 用户指向以 Lua 表达技能专属定义，包括目标形态、目标关系、效果类型和技能组合流程；执行方式等具体内容归类由程序依据业务语义核实。配置表达不能自行替代权威门控、命中及实际效果。
- 高频反复调试的纯数值放 JSON，例如经核实适用的伤害、距离、速度、范围或时长；已确认的样本值和既有结果保持一致。目标关系、效果类型和组合流程不是仅因可配置就归入纯数值。
- 旧内容、数值及目标规则应建立可对照版本；不从未核实的实现推定策划规则。若某项不能清晰归类或迁移后产生行为差异，记录影响并回交确认。
- 不规定具体字段、schema、API、编辑工具、热更新或安全策略；不新增玩法、受击/VFX 新体验或前后摇操作规则。

## 基建依赖与交接

内容表达依赖[通用技能基建需求](SkillInfrastructureRequirements.md)提供技能请求与 Ability 生命周期、目标合法性、执行和效果结算、释放事件、状态与终态等现有技能所需共用能力；内容选择或组合不等于结果已经发生。基建能力与配置内容的具体接口由程序 PM 和架构 Agent 统一核实，缺口及影响须明确记录。四技能业务摘要、共同约束和旧需求取代关系见[共同约束](SkillChainRefactorRequirements.md)。

程序 PM 统一安排架构接口、实现及 Review。配置生产实施须交由不同于 C++ 通用基建实现职责的适当负责人承担；不将全部配置迁移混派给基建实现职责。实际负责人数量及技术任务拆分由 PM 在架构后确定。

## 独立验收

| 场景 | 通过条件 |
| --- | --- |
| 范围与清单 | 程序提出实际技能迁移清单、内容版本、未覆盖项和证据；代表性样本不自动构成完整清单 |
| 技能专属定义 | 对已纳入范围的内容，检查目标形态、关系、效果类型和组合按确认的 Lua 方向表达，技能专属定义不硬编码 C++；记录确有疑义的分类和处理 |
| 纯数值 | 核对高频可调纯数值由 JSON 承载，冻结迁移前后对照值；修改选定数值时只有预期数值结果变化，不改变未授权的业务行为 |
| 代表性内容对照 | 根据确认的迁移范围，分别以适用的 Fireball、AreaBurst、Mend、BurningBuff 验证目标、执行、实际效果及持续状态与改造前一致；未执行样本明确标为待验证 |
| 依赖与证据 | 对每项纳入内容记录所需共用能力、对照方式及未满足依赖；配置可读或脚本返回成功不能替代实际技能运行结果 |

现有技能、数值、内容载体和运行行为均待程序核实。本需求不宣称内容已经迁移或通过验收。
