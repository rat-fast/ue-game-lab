# 技能系统链路改造共同约束与样本验收

本文是两类需求的共同约束和跨线验收入口；独立交接分别读取[通用技能基建需求](SkillInfrastructureRequirements.md)和[技能配置生产需求](SkillContentProductionRequirements.md)。本文件的职责表为两者关系摘要，不替代各自范围和验收。

## 1. 目标、来源和范围

本轮用户要求改造 SkillLab 当前 GAS 技能链路及内容生产边界，目标是把可复用的稳定规则与技能专属定义区分开，使内容可维护，并保持既有玩家可观察行为，不新增玩法。依据为本轮用户方向与 [SkillSystem 共享基线](../../../../Baseline/SkillSystem/README.md)；[旧 Batch02 需求](../Batch02-LuaSkillCompositionPilot/LuaSkillCompositionPilotRequirements.md)提供相容的既有样本背景。基线未证明迁移或行为等价已完成。

**通用适用范围**：面向当前技能系统的公共技能请求、激活与施法、目标、执行、效果及终止等链路，以及技能内容生产边界。具体受影响的现有能力、技能和实现链路，由程序 PM 核实；不依据四技能样本断言其他能力已存在。

**可验证样本与内容迁移**：共享基线中的 Fireball、AreaBurst、Mend、BurningBuff 是代表性案例及验收样本，不构成通用设计的上限，也不预先决定必须迁移的技能数量或完整清单。实际迁移范围及交付顺序由程序核实、任务拆分并回交确认。

**排除**：Batch01 六技能新增内容迁移和玩法扩展、前后摇操作规则、受击/VFX 新体验、工具、UI、热更新和安全策略。排除新增内容迁移不限制通用职责边界面向整个当前系统。资源、冷却、取消、死亡和 Reset 等维持既有行为，本轮不新定操作或补偿规则。

## 2. 通用职责和内容边界

| 职责 | 本轮方向和约束 |
| --- | --- |
| 稳定共用规则与机制 | 公共请求受理、资格与目标合法性、资源/冷却、权威命中和实际效果、持续状态、终态与清理等能力按既有业务规则执行；具体机制、归属及已有能力由程序核实。公共机制不应为单个技能硬编码专属定义。 |
| 技能专属定义与组合 | 技能专属定义不应硬编码 C++。用户倾向以 Lua 表达目标形态、目标关系、效果类型和技能组合，包括技能选择的执行方式和流程；可表达内容及调用边界由程序核实，不借此引入新玩法。 |
| 高频纯数值 | 用户倾向由 JSON 承载高频可调的纯数值，例如经核实适用的伤害量、范围或时长；数值是否属于该类以实际语义核实，不把目标关系、效果类型或技能组合直接当作纯数值。现有值与结果保持一致。 |
| 激活与施法 | GAS Ability 负责激活和施法生命周期，并在有效释放事件后正式推进释放及效果提交；不由内容定义或动画自行宣告业务成功。 |

Lua/JSON 是用户指定方向及倾向，不在策划中规定 API、schema、载入流程、插件、类组织或实现步骤。技能意图、目标候选、脚本返回值和动画信号不等于实际命中或效果；真实结果由权威技能运行层结算并供表现消费。现有能力不足或分类存在歧义时，由程序提出影响和待确认问题。

## 3. 生命周期与释放事件

1. 请求与目标意图不等于已施法、命中或产生效果；GAS Ability 负责激活及本次施法生命周期。
2. 到达动画 Cast Notify 时，发送带 Tag 的 Gameplay Event，通知当前施法的 Ability 到达释放时点。具体 Tag、事件载荷、绑定、适用技能与动画资源现状由程序和表现侧核实。
3. 当前 Ability 接收到适用于本次施法的释放事件后，按既有规则正式推进释放，并负责推进相应效果提交。事件只表达到达释放时点，不直接证明命中、伤害、治疗或持续效果已发生；投射物等后续结果按既有行为发生，不要求事件到达时立即命中。
4. 事件和后续结果须归属正确的当前施法。重复、迟到、无关 Tag 或已结束施法的事件不得使效果、费用或终态重复，也不得推进后续施法；具体识别方式由程序确定。
5. 释放前终止、目标失效、缺失或重复 Notify、动画中断及 Reset 的既有行为须核实。不得为填补未知行为擅自制定新的前后摇操作、退款、超时或兜底策略；无法兼顾事件链与既有行为时记录差异并提交决策。

表现继续反映实际技能事实。Cast Notify 是释放时点信号，不由动画自行结算效果或宣告命中。现有资源缺失或延迟时的行为及与新链路的兼容性须核实，本轮不增加受击或 VFX 体验。

## 4. 已有代表性样本

| 样本 | 共享基线确认的目标和执行 | 效果与对照重点 |
| --- | --- | --- |
| `Skill_Fireball` | 敌方单位，投射物 | 伤害；核对命中、阻挡和未命中等既有结果 |
| `Skill_AreaBurst` | 地面位置，作用于范围内敌方单位 | 伤害；核对多目标和空区域等既有结果 |
| `Skill_Mend` | 自身，即时目标 | 治疗；核对实际恢复和满生命结果 |
| `Skill_BurningBuff` | 敌方单位，即时施加持续效果 | 持续伤害；既有样本持续四秒、每秒一次；周期与移除事实独立于施法终态 |

以上仅为代表性样本，不能推导其他技能不存在或不受公共链路影响。四秒和每秒一次是该样本参数，不是通用持续效果规则。其他数值、范围边界、资源和冷却时点尚未由共享基线冻结，应建立迁移前后可比内容与证据，不能由策划臆定。

## 5. 与旧 Batch02 的关系

旧需求第 3、4、11 节将 Lua 限定为流程组合、限制目标关系和效果类型等内容归属的表述，在本轮通用改造范围内由第 2 节方向取代。旧第 5、6 节中禁止表现回调推进技能、动画不能参与业务推进的泛化表述，由第 3 节 Cast Notify → 带 Tag 的 Gameplay Event → 当前 Ability 正式释放契约取代；动画信号仍不等同于命中或实际效果。旧需求中表现资源缺失时逻辑必然照常推进等绝对结论，在依赖 Notify 的新链路中不预设成立，交程序/表现核实并保持既有行为。

旧文档相容的样本目标、实际效果权威、施法与持续效果区分及不新增玩法原则仍可参考；未由共享基线确认的具体失败、清理、身份或阶段规则不是本轮新增承诺。共享基线保留原状，本需求不宣称实现或验收完成。

## 6. 验收

程序先核实当前系统及具体受影响链路，并提出实际迁移和验证范围。以改造前可复现行为及冻结的同一内容版本为对照，在相同输入和初始状态下比较改造后结果；记录环境、事件顺序、目标、实际效果、资源/冷却与终态。对照路径能否并存由程序核实；不能并存时保留改造前证据。以下均待验证。

| 场景 | 通过条件 |
| --- | --- |
| 通用职责 | 审查程序核实的当前公共链路和受影响技能：稳定共用机制与技能专属定义边界符合第 2 节，专属定义不硬编码 C++；覆盖范围和未覆盖项明确，不仅凭四个样本推断全部完成 |
| 内容边界 | 验证适用的目标形态、关系、效果类型和组合可由 Lua 内容表达；高频可调纯数值由 JSON 承载。调整已确认数值只产生预期变化，不改变未授权业务行为 |
| 释放时点 | 对实际适用技能观察 Cast Notify、带 Tag 事件、当前 Ability 正式释放及后续结算；释放不早于有效事件，事件本身不伪造命中或效果 |
| Fireball 样本 | 合法敌方、命中、阻挡及未命中等可复现场景与改造前一致；投射物实际结果和伤害不重复 |
| AreaBurst 样本 | 多目标、空区域及无效位置等可复现场景与改造前一致，实际受影响对象和伤害一致 |
| Mend 样本 | 受伤及满生命时仅对自身产生与改造前一致的实际治疗结果 |
| BurningBuff 样本 | 敌方施加、四秒/每秒周期及结束移除与既有样本一致；施法结束不等同于持续效果结束 |
| 事件隔离和终止 | 重复、错误 Tag、迟到事件及取消、死亡、Reset、目标失效等可复现场景，不重复释放、费用、效果或终态，不影响新施法；其他结果与改造前对照 |
| 动画依赖 | 对照适用技能既有 Notify、无 Notify、动画中断或缺失时的可观察行为；无法保持时记录差异和待决事项，不自行宣告通过 |

样本验证的执行方式应与最终确定的迁移及任务拆分范围对应；未纳入本轮执行的样本明确标为待验证，不能以通过的样本替代通用链路覆盖证据。

## 7. 未决事项与核实清单

**待澄清**：实际需要迁移哪些技能、数量和交付顺序；哪些现有数值及内容版本用于冻结对照；若既有释放不依赖动画或技能没有可用 Notify，如何兼顾既有行为与新契约；异常时玩家可观察结果和终态映射若无法从既有行为确定，需产品确认。本轮不预设补救机制。

**程序及表现侧核实**：

- 当前技能系统公共能力和真实调用链、受影响技能与已有内容生产路径；给出影响清单、迁移和验证范围建议，并标明证据及未覆盖项。
- 稳定公共机制与技能专属定义目前的分布；目标形态、关系、效果类型和组合交由 Lua 表达及高频纯数值放入 JSON 的可行边界，以及保持权威结算所需能力。
- 可复现的请求、目标、释放、命中、实际效果、持续状态、资源/冷却、取消与 Reset 行为和对照证据；核实基线未冻结参数及异常路径。
- 相关技能既有动画及 Cast Notify 的有无、位置和触发条件；缺失、中断、重复或延迟时的现有结果，以及释放事件契约的适用性。
- GAS Ability 激活、生命周期、带 Tag Gameplay Event 的接收、当前施法关联和正式释放/效果提交的接入点；Tag、载荷、身份、事件顺序及重复/过期处理。
- 目标合法性、实际命中与效果、持续效果身份和移除是否保留原结果；事件与投射物或持续效果后续生命周期的关系。
- 原有与改造后对照的可执行方式、需冻结的数据及记录；存在差异或无法兼容时，明确影响和需要产品决策的选项。

程序线据此核实并设计实现；表现线核对既有动画事件时点和资源条件；验证线执行经确认的第 6 节范围并记录证据。以上是需求或待核实项，不代表已实现、已运行或已验收。
