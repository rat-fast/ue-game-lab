# 通用技能基建需求

## 目标与范围

面向 SkillLab 当前 GAS 技能系统整体，提供运行现有技能所需的共用能力和一致的业务约束，使技能专属定义可以由内容表达，同时保持既有行为。适用范围不以四个样本为上限；具体现存能力和受影响链路由程序 PM 核实。本文提出公共能力要求，不规定类、模块、API 或实现步骤。

本轮不新增玩法或前后摇操作规则，不将 Batch01 六技能新增内容迁移、受击/VFX 新体验、工具、UI、热更新或安全策略作为交付要求。实际技能迁移范围待程序核实和任务拆分确认。

## 共用能力和业务约束

- 支持统一技能请求与运行：区分输入意图、请求受理/拒绝和正式施法，遵循已有资格、目标合法性、资源与冷却规则；是否及如何提供这些能力须核实。
- GAS Ability 负责激活及施法生命周期。动画 Cast Notify 通过带 Tag 的 Gameplay Event 通知当前 Ability 到达释放时点，由 Ability 正式推进释放与效果提交。事件仅表示时点，不等于命中或实际效果；投射物和持续效果等后续过程保留既有行为。
- 提供内容所需的通用目标、执行与效果能力，供技能定义选择与组合；权威运行层产生实际目标、命中、伤害、治疗、持续状态及移除等事实，表现消费事实，不自行结算。
- 请求、当前施法、执行和持续效果的关联及清理应足以保持既有行为；重复、迟到、无关 Tag 或已结束施法的事件不得重复释放、费用、效果或终态，也不得推进新施法。取消、死亡、目标失效和 Reset 的具体旧行为先核实，不擅自发明退款或兜底规则。
- 释放时点和通用能力不固化为 Fireball、AreaBurst、Mend、BurningBuff 的专属规则。技能专属目标形态、关系、效果类型和组合不硬编码 C++。

## 依赖与交接

本需求依赖[技能配置生产需求](SkillContentProductionRequirements.md)提供经确认的技能内容语义和可用于对照的内容版本；基建向配置生产提供能够表达并执行现有内容所需的能力和事实，双方的接口由程序 PM 和架构 Agent 核实确定。动画时点需表现线核对。共同范围、旧需求取代关系和样本见[共同约束](SkillChainRefactorRequirements.md)。

程序 PM 统一安排接口、实现和 Review；基建实现职责与配置生产实现负责人分开，具体 Agent 数量及技术拆分在架构后确定。不得因尚未确定配置迁移数量，忽略对当前系统公共链路的影响核查。

## 独立验收

| 场景 | 通过条件 |
| --- | --- |
| 公共能力覆盖 | 程序列出核实过的当前链路、受影响能力和未覆盖项，说明技能专属定义与共用机制的边界；四样本不能单独证明整个系统覆盖 |
| 激活与释放 | 对适用链路观察 Ability 激活、Cast Notify、带 Tag 事件、当前 Ability 推进释放及实际结算的关系；事件本身不伪造效果，释放不早于有效事件 |
| 身份和终态 | 重复、迟到、无关事件及已终止施法不造成重复释放、费用、效果或终态，也不影响新施法；取消、死亡、目标失效和 Reset 与可复现的原行为对照 |
| 效果与持续状态 | 根据确认的验证范围，对照实际目标、命中、伤害、治疗和持续状态事实；持续效果结束不能仅凭原施法结束推定 |
| 动画依赖 | 核实既有 Notify、缺失、中断、延迟情形与改造前行为；冲突记录影响和待决项，不能默认验收通过 |

验收前应冻结可复现对照与适用范围；结果及缺口须记录。技术链路、资源现状和全部运行结果目前均待程序/表现侧核实。
