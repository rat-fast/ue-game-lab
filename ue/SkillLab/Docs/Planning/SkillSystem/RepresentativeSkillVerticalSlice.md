## 项目与系统目标

SkillLab 是用于学习 UE 研发职责和验证 AI 内容生产的实验项目。当前方向为单机实时战斗、俯视角、MOBA 式操作与 ARPG 式技能效果丰富度。

技能系统目标是建立可扩展的公共能力，支持玩家、敌人、友方及测试调用，让重复技能内容能够在共同底座上实现，并通过试玩检验运行、反馈、清理和复用。

项目运行事实见 ProjectContext，程序实现与验证见 ProgramWorkflow；技术选择由程序线说明。GAS 可作为运行基础的技术方案，具体职责与内容载体随样本验证确定。

## 总体能力范围

| 领域 | 需要表达的能力 |
|---|---|
| 单位 | 阵营关系、属性资源、可用技能、授予撤销、死亡、复活/重置 |
| 施法 | 请求与拒绝、前摇/释放/收招、取消中断、资源冷却、可选缓冲、引导多段 |
| 目标 | 自身、单位、地面、方向；敌友与中立过滤；预览、确认、查询、命中重检 |
| 执行 | 直接、投射物、范围/扇形/直线、持续区域、位移 |
| 效果 | 伤害、治疗、护盾、增减益、控制、免疫驱散、瞬时/持续/周期、叠加刷新 |
| 反馈与验证 | 动画/特效/音频/UI 业务事件、失败原因、对象/状态清理、重复运行 |

成熟度目标是可持续承载多种技能组合。总体能力与当前六技能批次的交付覆盖分开记录，扩展依据真实内容需要和运行结果修订。

最终游戏类型、职业/装备/成长体系、多人需求、DSL、是否全部由文本生成均保持开放。

## 能力覆盖与验收

| 覆盖组 | 证明样本 | 可观察结果 |
|---|---|---|
| 单位/阵营/单体 | 火焰弹、治疗、护盾 | 敌我过滤、失效拒绝、实际伤害/治疗/吸收 |
| 空间 | 火焰弹、扇斩、烬地 | 弹体、方向/位置快照、多目标去重、区域存续 |
| 阶段 | 扇斩、光束 | 前摇/收招、段推进、资源时点、取消/受伤中断 |
| 持续状态 | 火焰弹、烬地、护盾 | 刷新、贡献聚合、耗尽/到期、来源追踪 |
| 重置与反馈 | 全部 | 可见运行、失败原因、死亡/Reset 清理后再次运行 |

场景需有可控制玩家、敌方和友方单位、地面与技能阻挡物，能观察生命、能量、速度、状态及对象；提供可重复初始条件和取消、中断、死亡、重置操作。

每个技能有可操作的试玩路径，能分辨预览、释放、命中/无命中、维持、结束与失败。基建能力按独立用例验收，技能按自身结果验收；参数变体检验复用。

## 整体推进与当前交接

按用户确定的方向，六个技能共同界定一批基建需求，随后由技能侧调用公共能力实现内容，在同一场景试玩。两类策划可以相互校验，基建交付也需要实际调用证明。

| 产物 | 当前策划状态 | 后续使用 |
|---|---|---|
| 基建需求 | 公共规则、九模块长期能力和 Batch01 实施子集已整理 | 用户 review；程序核对能力与接口缺口 |
| 技能配置 | 六个技能首轮建议稿已整理 | 用户 review；按公共接口实现技能内容 |
| 技术接口 | 由程序线维护，当前文档仍含技术样本范围 | 程序确认本批可用能力及缺口 |
| 试玩结果 | 策划稿中用例均待运行 | 程序/表现接入后记录实际结果 |

用户 review 重点为追踪弹体、前摇移动取消、按住引导及受伤打断、区域源死亡处理、满血治疗成本、减速与护盾重施。参数和手感随试玩调整。

详细规则各归本层正文，技术映射与运行流程见 [程序入口](../../ProgramWorkflow/SkillSystem/README.md)。
