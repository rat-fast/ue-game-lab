# M05 属性、效果与状态（详细设计草稿）

## 定位

M05 定义技能命中后如何改变单位，以及属性、资源、效果和持续状态如何关联。

已确认：需要属性、资源、伤害、治疗、护盾、增益、减益、控制、驱散、免疫、瞬时/持续/周期效果。
AI 建议默认方案：数值公式、叠加优先级和特殊免疫规则由具体技能样本逐步确认。

## 职责

负责属性修改、资源变化、效果应用与移除、状态添加与清除、叠加/刷新/覆盖、免疫和效果来源追踪。

不负责输入、目标查询、技能阶段推进、投射物运动或表现资源播放。

## 核心边界

- 属性是可被读取和修改的数值；资源是参与激活或持续执行的属性类别。
- 效果是一次改变行为或应用操作；状态是改变发生后持续成立的运行事实。
- 伤害、治疗、护盾是效果类型；眩晕、沉默、减速、免疫是状态或状态相关语义。
- 每次效果必须能关联施法实例、来源技能、施法者、目标和发生时间。

## 推荐处理链

命中事件
→ 检查目标有效性、免疫和效果条件
→ 计算修改
→ 应用瞬时效果或建立持续效果
→ 添加/刷新/移除状态
→ 发布属性和状态变化事件
→ 记录结果并在结束时清理

效果应用失败不能伪装成命中成功；目标免疫和目标失效需要提供可观察原因。

## 叠加与持续规则

技能定义需要声明：

- 是否允许同类效果叠加；
- 新效果覆盖、刷新时长还是独立计时；
- 最大层数；
- 驱散优先级；
- 控制是否可被免疫；
- 周期效果的第一次触发时点；
- 施法者死亡后效果是否继续。

首版建议同类效果默认使用“刷新时长”或“独立实例”二选一，不允许每个技能私自发明隐藏规则。

## 配置与固定约束

可配置：属性类型、公式、强度、持续时间、周期、层数、免疫标签、驱散类别、护盾消耗顺序和来源。

固定约束：

- 效果必须经过统一应用入口；
- 技能不能直接写目标属性绕过效果系统；
- 免疫、驱散和叠加结果可追踪；
- 移除效果必须幂等；
- 重置和死亡清理不能留下持续修改或状态标签。

程序可选择 GameplayEffect、AttributeSet、标签和自定义执行计算的组合。

## 需要用户重点确认

- 控制和免疫的优先级；
- 护盾与生命伤害的顺序；
- 同类效果默认刷新还是叠加；
- 死亡后持续效果是否继续；
- 驱散是否区分增益、减益和控制。

## 交接

M02 提供属性和标签环境；M03 提供施法来源和阶段；M04 提供合法命中；M06 提供空间命中；M07 订阅变化；M09 记录效果结果。

## 实现交接补充

效果应用输入必须包含 CastId、EffectId（由应用方分配）、来源技能、施法者、目标和效果参数。输出必须包含 Applied、Immune、InvalidTarget、Blocked 或 Failed 之一，并说明实际修改值。

属性修改、状态添加和状态移除都必须经过统一入口。即时效果完成后保留结果事件；持续效果保留可移除的 EffectId；周期效果每次触发都带序号，避免把一次应用和多次触发混为一谈。

默认清理顺序是先停止周期触发，再移除由本次技能创建且规则要求随技能结束清理的状态，最后发布移除事件。已经结算的即时伤害和治疗不回滚。
