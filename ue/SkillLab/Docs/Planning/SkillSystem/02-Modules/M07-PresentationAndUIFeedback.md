# M07 表现与 UI 反馈（详细设计草稿）

## 定位

M07 把技能系统的运行事件连接到动画、特效、音频、镜头、UI 和调试显示。表现层不重新决定技能规则。

## 职责

负责事件订阅、资源绑定、播放时机、缺失资源回退、技能槽位状态显示、预览显示、冷却和结果反馈。

不负责激活判定、伤害结算、命中过滤、资源扣除或施法状态机。

## 事件分类

- 预览开始、更新、确认、取消；
- 请求接受、拒绝、缓冲、开始；
- 前摇、释放、引导、收招、打断、完成；
- 投射物创建、区域开始/结束、位移开始/结束；
- 命中、效果应用、状态添加/移除；
- 冷却开始/结束、资源不足、不可用原因；
- 死亡、重置和清理。

事件要携带来源、施法实例、目标或位置、阶段和结果原因；表现资源不应反过来决定是否命中。

## 配置与固定约束

可配置：动画、Niagara、音频、UI 图标、挂点、镜头反馈、缺失资源占位和事件到资源的绑定。

固定约束：

- 表现事件与逻辑结果解耦；
- 缺少表现资源不能阻止逻辑运行；
- 取消/打断必须能停止或切换对应表现；
- UI 显示是状态镜像，不能绕过系统提交结果；
- 预览表现不能被误当成正式命中。

## 需要用户重点确认

- 预览范围与命中特效是否必须区分；
- 前摇、命中、结束是否都需要独立表现事件；
- 技能被打断时动画和特效如何处理；
- 缺少资源时使用占位、静默还是日志提示。

## 表现事件契约

表现事件不是字符串通知，而是可追踪事实。至少包含 EventId、EventType、UnitId、SkillId、RequestId、CastId、Stage、WorldTime、位置/方向、目标、结果和 Reason；投射物/区域事件增加 ObjectId，效果事件增加 EffectId。

事件类型分为三类：

1. 瞬时事件：释放、命中、效果应用、失败提示、状态添加。
2. 生命周期事件：前摇开始、引导开始、区域开始、区域结束、冷却开始/结束。
3. 终止事件：取消、打断、死亡、重置、表现清理。

表现适配器按事件类型和内容配置选择动画、Niagara、音频、镜头和 UI。一个事件可以触发多个表现资源；资源不存在时不阻塞逻辑，并向 M09 记录缺失原因。

## 表现实例规则

播放实例保存 EventId、CastId/ObjectId、资源引用和停止策略。瞬时特效自然结束；绑定 CastId 的持续表现随取消、打断或对象销毁收到停止事件；重置必须停止所有仍被追踪的实例。重复事件必须按 EventId 或对象策略去重，不能重复创建不可回收表现。

UI 只读取装配、预览、冷却、资源、状态和请求结果；UI 操作提交请求或装配变更，不直接修改 ASC、冷却或效果。预览表现必须使用 Preview 标识，不能误用 Hit 或 EffectApplied 资源。

## 表现资源配置

配置至少需要表达事件类型、资源类型、资源引用、挂点/位置规则、是否循环、停止事件、缺失资源策略和可选参数。具体载体由程序决定，配置校验必须检查引用存在、停止事件匹配和循环表现是否有终止条件。

## 交接检查点

用 TestPulse 证明释放/效果/完成事件能被观察；用投射物证明创建、命中和销毁能关联 ObjectId；用引导或持续区域证明取消、死亡和重置能停止持续表现；用缺失资源配置证明逻辑仍完成且产生诊断。
