# M07 表现与 UI 反馈需求

## 状态与职责

建议稿，待用户 review 与试玩。本模块把运行事实转成可观察的预览、动画、特效、音频、镜头、UI 和调试反馈，不重新决定技能规则。

## 行为需求

- 区分预览开始/更新/确认/取消、请求拒绝/开始、前摇/释放/引导/收招/完成/取消/打断，以及命中、效果、对象和状态的生命周期反馈。
- 反馈携带来源、技能、施法、目标或位置、阶段、实际数值和结束原因；持续反馈绑定真实拥有者。施法结束后仍存续的弹体、区域或状态继续反馈自己的生命周期。
- UI 显示真实装配、预览、资源、冷却、阶段、生命、护盾、状态时间和拒绝原因。预览反馈不能伪装成正式命中或效果。
- 缺少资源不能阻止逻辑运行；使用清晰占位或静默策略并留下可诊断原因。取消、打断、死亡、移除和 Reset 必须能停止对应持续反馈。
- 同一运行事实只生成一次可追踪反馈；重复订阅或重复清理不产生残留表现。

## 业务输入输出

输入为预览事实、阶段事实、效果结果、对象/状态生命周期、绑定选择和缺失资源策略；输出为可见反馈实例、停止/清理回执和缺失资源诊断。动画、特效、音频和 UI 的具体载体由程序/表现线决定。

## 独立验收

- 代表性技能都能看出预览、释放、命中或无命中、维持和结束；实际效果值可辨认。
- 故意缺失绑定时逻辑仍完成，并有占位或诊断；区域、弹体和独立状态在源施法结束后仍能观察到正确生命周期。
- 取消、受击打断、目标死亡和 Reset 后没有持续表现残留；重复运行不会重复创建不可回收实例。
