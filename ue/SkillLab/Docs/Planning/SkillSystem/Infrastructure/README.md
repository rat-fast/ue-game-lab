# 技能系统基建需求

## 状态与使用方式

本目录是公共能力的长期策划目录，供用户 review；规则与默认值均为建议，尚未逐项确认或运行验证。当前第一批的实施范围见 [Batch01 六技能纵切片](Batches/Batch01-SixSkillVerticalSlice/README.md)，总体方向见上级核心文档。

基建实现先读本文件，再读当前批次目录中的输入链路、状态所有权、能力需求和验收矩阵，最后按批次矩阵涉及的职责读取模块。本文及模块中的独立输入输出和验收例子定义长期能力；具体技能参数和本批实施选择由批次与内容侧提交。程序决定实现接口、GAS 组织、对象存储与数据载体。

基建实现不要求先阅读 `Skills/`；只有验证公共能力覆盖某个技能，或公共接口发生变化时，才通过核心入口和交接记录与技能层对齐。

## 公共概念

| 概念 | 业务意义 |
|---|---|
| 单位 | 有身份、阵营、属性、状态和能力，可参与效果 |
| 技能内容 | 可重复使用的规则与参数描述 |
| 能力授予 | 某单位获得该技能的调用资格 |
| 槽位装配 | 输入槽位指向当前技能，区别于授予 |
| 请求 | 一次调用尝试，可拒绝或开始 |
| 施法 | 一次已开始运行，拥有阶段和结束原因 |
| 目标上下文 | 输入确认的单位、位置或方向，区别于实际命中 |
| 效果与状态 | 效果是改变操作，状态是改变后的持续事实 |
| 执行对象 | 弹体/区域等空间执行实例，可有独立存续 |
| 业务反馈 | 对运行事实的可见表现与诊断 |

一次运行可关联施法者、技能、请求、施法、目标、对象和效果。身份必须可追踪；具体技术字段和句柄由程序接口定义。

## 公共规则（建议默认）

1. 请求首先检查单位、授予、状态、目标、资源与冷却。拒绝不产生成本、冷却、正式效果或已开始施法。
2. 通过激活闸门才正式开始，资源和冷却按技能声明时点提交且仅一次。开始后的取消/打断默认保留已支付成本，内容可声明受支持的例外。
3. 正常完成、主动取消、规则中断分开记录；完成不等于命中。预览取消发生在开始前。
4. 每次施法进入终态一次，反复清理保持结果一致。已结算即时效果保留记录，持续效果按自身移除条件处理。
5. 单位、地面、方向确认快照与真实命中分离；实际候选要经过关系、存活、空间与效果合法性检查。
6. 施法、对象、状态可有不同结束时间；独立对象/状态保留来源，源施法结束后仍能定位、移除和重置。
7. 反馈读取真实阶段/效果结果；视觉资源缺失时保留规则执行、占位和原因。
8. 同时发生的业务事件依次处理重置/销毁/死亡、取消/阻塞、到期、阶段/周期、命中/效果。当前效果触发的死亡或受伤中断在下一效果/段前生效；同优先级的先后可复现。
9. 持续区间包含开始、不包含结束，终止后停止后续周期/段。护盾到期与伤害同刻时先到期再结算伤害。
10. 重置清理单位输入、运行施法、拥有对象、收到的持续效果及其对其他单位产生的持续输出，随后恢复初始条件；残留时报告具体拥有者与结果。

## 本层整体验收

- 同一组单位/目标/参数可由玩家、AI、测试得到一致的业务结果。
- 同步、异步对象、周期和引导都能追踪来源、独立终止与重置。
- 候选、命中、效果结果与完成分开可查。
- 故意输入非法内容或状态得到具体原因；成功结果有真实数值和反馈。
- 单位/场景多次重置恢复初值，无重复能力、状态、对象与持续表现。
- 可调内容改变运行结果，同时保持公共校验、结束与清理语义。

本层以这些独立用例交接。程序对外提供版本明确的能力接口、参数约束、调用例子与可用性；内容侧消费该接口即可。高级控制、驱散、位移等总体能力按实际任务扩展，当前规则保持明确的支持状态。

## 规则、配置与运行时状态的归属

| 类别 | 由谁决定 | 典型内容 |
|---|---|---|
| 基建固定规则 | 基建策划与程序公共接口共同维护 | 请求拒绝无副作用、成功开始闸门、身份追踪、终态幂等、对象/效果归属、Reset 清理和事件事实 |
| 内容配置 | 技能策划声明，程序提供加载与校验 | 按键映射、目标关系、成本、冷却、前摇/持续时间、范围/速度、伤害/治疗/护盾/状态数值、叠加策略和表现引用 |
| 运行时状态 | 运行时产生和维护 | 当前输入会话、操作意图、目标快照、Request/Cast、阶段、资源与冷却剩余、投射物/区域位置、效果剩余时间和实际结果 |
| 技术实现 | 程序线决定 | GAS 类、C++/Blueprint 边界、数据载体、序列化字段、对象存储和调度方式 |

模块正文只规定第一类能力及其对配置、状态的接口；具体技能数值和输入绑定不在模块正文中冻结。
