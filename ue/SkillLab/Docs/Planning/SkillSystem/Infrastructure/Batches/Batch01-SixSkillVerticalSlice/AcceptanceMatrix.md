# Batch01 基建验收矩阵

## 通过条件

本矩阵验证公共能力是否足以承载六个技能。具体技能体验验收从 [六技能索引](../../../Skills/SkillDesigns.md)进入对应独立正文。输入链路和状态归属分别以 [InputIntentRequestFlow](InputIntentRequestFlow.md) 与 [RuntimeStateAndOwnership](RuntimeStateAndOwnership.md) 为准。每项记录通过、失败或待运行，并保存实际参数、运行入口和结果身份。

## 能力验收

| 验收组 | 操作 | 必须观察 |
|---|---|---|
| 请求闸门 | 资源不足、冷却中、目标非法、未授予、死亡单位分别提交 | Rejected 原因可区分；无 Cast、成本、冷却和正式效果副作用 |
| 开始与终态 | 成功请求、主动取消、死亡中断、Reset、重复终止 | Started 只创建一次；终态唯一；清理幂等 |
| 单位关系 | Self、Ally、Enemy、Neutral 目标交叉请求 | 关系过滤准确；关系改变后目标失效；跨单位效果可清理 |
| 目标查询 | 单位、地面、方向、圆、扇形、直线带，含边界、隔墙、多组件 | 预览与正式查询一致；边界、视线、去重和重检正确 |
| 投射物 | 追踪目标、移动目标、墙体、目标死亡、时间/路径上限 | 候选统一过滤；命中/阻挡/到期各有结果；对象只销毁一次 |
| 持续区域 | 区域生成后施法者移动、成员进出、重叠区域、周期边界 | Cast 可完成而区域继续；周期按半开区间；成员贡献和尾效可清理 |
| 分段引导 | 启动资源、每段资源、松开、移动、受伤、护盾吸收、空段 | 首段支付检查正确；已执行段保留；后续段按终止原因停止 |
| 效果结算 | 伤害、治疗、护盾、减速、免疫、替换、到期、目标死亡 | 实际值、溢出、吸收、状态贡献和移除原因可追踪 |
| 反馈与诊断 | 缺失表现、取消、对象结束、效果移除、Reset | 占位/诊断不阻塞逻辑；持续反馈无残留；事实不重复生成 |
| 调用一致性 | Player、AI、Test 使用相同技能、目标和参数 | 业务结果一致，来源不同但身份链完整 |

## 六技能覆盖

| 技能 | 必须证明的公共能力 | 最小成功证据 |
|---|---|---|
| Firebolt | 单位目标、敌方关系、前摇取消、追踪投射物、阻挡、伤害、减速刷新 | 按技能文档的具体数值命中一次；对象和状态可追踪、可 Reset |
| Mend | Self/Ally、瞬时治疗、实际值/溢出、满血 NoChange | 按技能文档的治疗量返回实际值、溢出和 NoChange；成本/冷却按声明执行 |
| ArcStrike | 方向快照、扇形、视线、多目标去重、前摇/收招 | 每个合法目标只结算一次；空范围完成；边界和隔墙结果正确 |
| BurnField | 地面合法性、独立区域、周期、成员贡献、离开尾效 | 按技能文档的周期执行；Cast 完成后区域继续；Reset 清理全部贡献 |
| ChannelBeam | 持续会话、分段资源、直线带、受伤/护盾打断 | 按技能文档的段策略推进；松开或有效受伤停止后续段 |
| Barrier | Self/Ally、护盾吸收、Replace、到期/耗尽、独立存续 | 按技能文档的容量吸收；新应用失败保留旧护盾；目标死亡/Reset 清理 |

## 批量回归

1. 以固定初始模板创建玩家、敌方和友方单位，授予六技能并记录来源。
2. 按技能逐项执行成功、非法、取消/中断和 Reset 用例；每项生成独立 RequestId/CastId 或等价追踪。
3. 重复运行至少两轮，确认技能冷却、对象、效果、状态、输入会话和表现没有跨用例残留。
4. 修改一项伤害、范围、速度或持续时间参数，校验通过后确认实际结果随参数变化，同时公共终止和清理语义不变。
5. 汇总设计完成、能力可用、技能组合、表现反馈、运行通过/失败/待运行和能力缺口。
