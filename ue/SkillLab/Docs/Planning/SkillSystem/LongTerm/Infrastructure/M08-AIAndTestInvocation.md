# M08 AI 与测试调用需求

## 状态与职责

建议稿，待 review。本模块定义玩家、AI、测试如何以不同来源提交同一类技能请求，并提供批量复现、设定条件和重置检查；不建立绕过正式规则的特殊施法路径。

## 行为需求

- Player、AI、Test 可以跳过物理按键或预览，但从请求开始共用正式激活、目标、效果、阶段、取消和清理语义。
- 调用可指定已授予技能、单位、目标单位/地面/方向、维持与停止；开始、维持、停止会话必须各有结果。是否允许未装槽但已授予技能由调用规则明确。
- 测试可设置生命、能量、位置、移动、受击、死亡、控制、对象/效果移除和 Reset 条件；设定条件与正式施法结果分开记录。
- 批量运行保存样本编号、参数、调用时点和身份；每组完成后 Reset 并检查跨单位效果、对象、状态、表现和冷却残留。失败需保留具体原因并结束当前用例。
- 测试工具可显示更多诊断，但不能改写正式成本、命中、效果或生命周期规则。

## 业务输入输出

输入为来源、单位、技能、目标规格、会话动作、初始条件和样本编号；输出为统一请求/施法/效果结果、复现记录、Reset 报告和残留诊断。AI 决策编排与测试执行器不属于本模块的技能规则。

## 独立验收

- Player、AI、Test 对相同单位、技能和目标得到一致业务结果，且来源可追踪。
- 代表性样本重复运行无跨用例残留；维持技能的开始、维持、停止结果与玩家调用一致。
- 一次失败保留拒绝/中断原因，Reset 成功后下一用例仍可独立开始。
