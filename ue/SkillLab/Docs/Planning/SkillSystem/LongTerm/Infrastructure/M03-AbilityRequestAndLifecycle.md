# M03 技能请求与施法生命周期需求

## 状态与职责

建议稿，待 review。公共语义见 [基建入口](README.md)。本模块接收统一请求，管理激活、阶段、成本、冷却、占用、取消、中断和终态。

## 激活与阶段

- 请求包含来源、施法者、技能与目标上下文。首先校验定义、初始化、授予、死亡/状态、资源、冷却与目标；拒绝保持未开始。
- 通过运行能力接受闸门后正式开始，捕获内容与目标，提交启动成本/冷却并推进阶段。
- 支持同步释放、前摇、释放、收招、引导分段和等待执行对象。阶段行为由技能侧声明，阶段时间、支付与终止由公共能力执行。
- 释放重检目标失败、执行创建失败中断并记录原因，默认保留已支付成本；正常空命中可以完成。
- 施法完成策略允许：等执行对象结束、对象创建后、效果应用后、引导结束后。对象和持续状态分别按其合法存续期继续。
- 同单位最多一个前台施法占用：前摇、收招、引导。占用期间其他激活拒绝并说明 Busy；已释放弹体等待结果、独立区域/状态不占前台。

## 成本、冷却与输入

- 激活成功后按技能声明的时点提交启动成本并开启技能冷却；冷却按单位与技能记录，换装是否影响它由规则声明。
- 分段成本与启动成本分开。可声明启动时检查首段可支付；每段前重检条件，再扣当段一次并执行，空段/多目标都只支付一次。
- 每段支付失败以资源不足中断，当段及后续停止。已结算即时结果保留。
- 前台开始停止导航并转向确认目标/方向；移动命令先取消可取消前台，再执行移动。内容可声明不同移动/转向策略。
- 预览取消与已开始取消分开；输入维持/停止携带原施法会话，避免换装误调用。
- 普通受伤事实为实际生命损失或护盾吸收大于 0。内容声明是否打断；死亡、Reset、阻止施法的控制通知活跃施法停止。

## 缓冲与异常

可选单次缓冲保存最近请求，声明时长、覆盖、适用阶段和重试；重试重新检查，换装/死亡/重置使旧待请求失效。是否启用由批次或游戏规则声明。

外部结果区分拒绝、开始、正常完成、取消、中断、缓冲/过期。阶段/对象结束与效果成功分别可查。清理反复调用只产生一次终态。

## 业务输入输出与依赖

输入为定义与目标上下文、阶段/支付/占用/完成策略、会话维持、对象回执与生命周期通知。输出为拒绝/阶段/支付/冷却/终态及清理结果。

M02 提供单位和资格，M04 重检目标，M05 修改资源/效果，M06 执行空间调用，M07/M09读取事实。具体函数、任务、身份字段由程序映射。

## 独立验收

- 启动成本高于当前资源的请求拒绝且无副作用；足够资源时只扣一次。
- 具有前摇和收招的请求正确占用；等待独立对象结果时按占用策略处理其他技能。
- 引导启动成本与分段成本分开；中段资源不足仅保留已执行段。
- 取消、死亡与 Reset 同刻发生按公共规则取唯一终态，后续段停止。
- 创建失败与正常零命中可区分；冷却与成本结果能解释。
