# 请求与施法生命周期

## 职责

说明请求受理、施法运行与终态的业务边界，不定义内部阶段 API、调度器、回调、具体时长或资源提交技术。

## 当前承诺

- 请求可能在施法建立前被拒绝；被拒绝的尝试不能被表现或脚本描述为已成功施法。
- 受理后的施法是有独立身份的运行过程，可产生阶段、效果、取消或完成等事实。
- 取消与完成是不同的终态事实。某个阶段或动作结束不自动证明技能效果已发生；效果已发生也不因后续表现失败而被伪造或抹除。
- 稳定共用运行机制由 C++/GAS/Runtime 提供，技能专属定义由 Lua 表达，高频反复调试的纯数值由 JSON 承载。Lua 内容不能取代权威门控、目标验证或效果结算。
- GAS Ability 承担激活和施法生命周期。动画 Cast Notify 通过带 Tag 的 Gameplay Event 通知当前 Ability 到达释放点，由当前 Ability 推进正式释放和效果提交；事件只表达时点，不证明实际命中或效果。
- 用户确认的操作规则适用于当前技能系统：闪避请求先取消当前施法，再尝试正式激活，激活仍可失败；普通受击不打断，重击打断；沉默/硬直阻止新技能激活并打断当前施法；移动与主动取消不打断；Recovery 期间不激活新技能。阶段名称本身不自动决定操作规则，时序窗口与操作策略是可组合的不同语义。
- 输入缓存采用单槽 latest-wins，只缓存下一技能意图。当前施法自然完成并退出 Recovery、旧 Cast/Ability 清理后，才以新请求身份重新经过正式激活、目标、资源和冷却门控；缓存消费不保证激活成功。取消、死亡、Reset 清除缓存。
- 资源与冷却在效果/释放提交时发生；提交前取消不扣费，提交后不退款或回滚已提交事实。Notify/Gameplay Event 超时或 Ability 中断会取消，不自动补发效果。每个已声明提交点在每个 Cast 中最多成功一次；重复触发忽略或拒绝，不因重复本身取消 Cast。

## 当前实现与验证

通用运行基建与四项内容迁移已经交付，相关独立 Review 通过；定向自动化和 NullRHI RuntimeProbe 提供有限运行证据。用户报告当前技能能在游戏中正常释放，作为基本流程观察记录；该观察不代表所有技能场景等价或正式 PIE 全面验收。证据来源、覆盖和缺口见 `07-ContentBoundary.md`。

## 当前限制与待确认

自然完成后的缓存重新门控消费由本轮策划确认并有定向实现证据；正式内容的端到端接入仍有缺口。Notify 超时到期、状态和攻击类别生产来源、多个技能配置差异及可见 PIE 尚未完整验证。资源/冷却以外的失败终态映射、Reset 对一般运行状态的精确恢复，以及 Notify 缺失/中断与既有行为的兼容对照仍按 `07-ContentBoundary.md` 所列证据判断。
