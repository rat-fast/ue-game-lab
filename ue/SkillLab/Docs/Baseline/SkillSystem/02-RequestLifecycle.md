# 请求与施法生命周期

## 职责

说明请求受理、施法运行与终态的业务边界，不定义内部阶段 API、调度器、回调、具体时长或资源提交技术。

## 当前承诺

- 请求可能在施法建立前被拒绝；被拒绝的尝试不能被表现或脚本描述为已成功施法。
- 受理后的施法是有独立身份的运行过程，可产生阶段、效果、取消或完成等事实。
- 取消与完成是不同的终态事实。某个阶段或动作结束不自动证明技能效果已发生；效果已发生也不因后续表现失败而被伪造或抹除。
- 稳定规则由 C++/GAS 执行权威；Lua 组合或表现回调不具备改变该权威的业务权限。该职责方向不等于本批已实现或通过验收。

## 当前限制与待确认

具体门控顺序、阶段集合、释放时点、资源/冷却提交和退款、失败到终态的映射、Reset 细则，只有经当前策划确认并以稳定实现/验证支持后才可纳入本篇承诺。相应业务选择目前待确认或待验证。
