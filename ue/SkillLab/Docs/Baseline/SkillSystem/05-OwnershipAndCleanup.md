# 持续效果与清理边界

## 职责

记录施法、持续效果和表现之间的业务区分，不定义运行对象归属、取消实现或重置工具流程。

## 当前承诺

- 施法动作或施法终态与独立持续效果不是同一生命周期。动作结束不证明持续效果结束。
- 持续伤害的周期结果及结束/移除事实由技能运行层产生，表现不得自行延长、结束或补造。
- 取消、完成、效果移除和系统重置是不同的运行事实；没有当前确认的规则不得推导其资源、效果或冷却后果。
- SkillCombatRules 确认缓存输入意图由当前施法仲裁生命周期管理：自然完成后延迟到旧 Cast/Ability 清理完成再重新门控消费；施法取消、死亡和 Reset 清除缓存。缓存不改变施法、效果或资源提交的所有权。

## 当前实现与验证、限制

迁移后 NullRHI RuntimeProbe 记录 BurningBuff 在施法后产生三次周期伤害，随后出现效果移除和跟踪清理事实；这是一个有限运行样本，不覆盖异常或死亡清理。SkillCombatRules 定向自动化与独立 Review 核验了缓存正常完成后的旧身份清理、新请求身份和取消/死亡/Reset 清槽机制；它没有验证缓存输入的可见 PIE 体验，也没有证明生产攻击类别或控制状态来源已接通。坏 reload 原子保持、缓存脚本快照行为及死亡后持续效果清理仍缺指定证据。具体证据与限制见 `07-ContentBoundary.md`。

Reset 的精确状态恢复、取消时持续效果处理、已结算即时效果保留规则以及重复施加行为，除已确认的样本语义外均待核实/确认。
