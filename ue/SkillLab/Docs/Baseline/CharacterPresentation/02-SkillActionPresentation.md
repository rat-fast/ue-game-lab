# 技能动作与表现事件

## 职责

定义表现消费技能真实事件的业务边界，不定义动作资源、Notify、Slot、时长或技术接口。

## 当前承诺

- 表现读取技能运行层的真实结构化事实。请求结果、阶段、目标/命中、实际效果、持续效果、取消和完成是不同事实。
- 动作、动画通知、特效和 Lua 回调不能自行宣告施法成功、命中、扣费、效果应用或施法终态。
- 动作应与对应施法关联；旧施法事件不得改变新施法的表现状态。该身份隔离是业务边界，当前实现正确性仍需运行验证。
- 动作终止与独立持续效果分开。燃烧等持续效果是否继续或结束由技能运行事件表达。
- 缺少动作资源时不能伪造或阻断权威技能结果；具体玩家可观察降级仍未确认。

## 当前实现与验证

2026-10-22 程序交接记录 C++/Lua 表现接入、四技能动作组件播放日志、燃烧效果在动作完成后继续运行的 NullRHI 观察，以及三项局部自动化通过。交接同时明确没有可见 PIE/视口验收，技能差异化可见反馈仍为占位表现，Fall 和旧/新 Cast 竞态缺少专门运行复现。当前相关源码和配置未提交，因此这些是进行中的实现证据，不是整批通过结论。

玩家反馈游戏内表现与改造前基本一致，仅是有限人工观察；不能替代上述缺失验收。

## 当前限制与待确认

尚未证实真实视口中的技能动作质量、Notify 与释放事件时点、取消/完成后姿势恢复、缺资源降级是否清晰、差异化技能反馈，以及旧事件竞态。具体技能动作选择和正式 VFX/音频方案不属于本基线承诺。
