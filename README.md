# AI Native 游戏研发工作区

本仓库不是单一 Unreal Engine 游戏项目，也不是为了在游戏玩法中加入生成式 AI。它用于探索 AI 如何在明确的专业语义、职责边界和验收依据下参与真实游戏研发，并将有效的方法逐步沉淀为人和 AI 都能使用的工作流、生产接口与工具。

## 核心思路

工作从真实的游戏研发任务出发，沿着“意图 → 结构化规格 → 代码、配置或资源 → 验证与 Review”组织。目标不是增加 Agent、工具或结构化格式的数量，而是让专业工作更容易被理解、交接、修改和检查，并根据实践结果决定哪些部分值得复用或自动化。

仓库的探索围绕两条相互连接的主线展开：

- **Agent 与工作流设计**：分析任务需要哪些判断、输入、输出和依赖，再决定如何安排人、Agent 和工具。多 Agent 是一种协作方式，不是预设目标；职责拆分需要有清楚的交付边界和上下文理由。
- **面向 AI 的生产接口**：理解代码、Blueprint、配置、资产和编辑器实际承载的领域语义，再为人和 AI 选择合适的生产表达。面向生产的领域表达可以不同于底层运行载体，但需要保留共同的业务语义。

这两条主线通过项目文档、结构化产物和可检查的结果连接。原则和方向见 [AI Native 游戏开发原则](AI_NATIVE_GAME_DEV_PRINCIPLES.md)；具体项目与任务的实现事实应以各自项目文档和交接材料为准。

## 仓库结构

- `ue/`：独立的 Unreal Engine 项目；每个项目位于自己的子目录。
- `docs/`：学习导航、研究材料和工作区历史记录。
- `.codex/skills/`：按职责路由的仓库级 Agent Skills。
- `ai/`：可复用的 AI 工作流上下文和配置。
- `tools/`：校验、生成、转换和自动化脚本。
- `schemas/`：结构化输入与产物的格式约束。
- `configs/`：引擎外部的配置源数据。
- `assets/`：外部参考资源和资源需求材料。
- `experiments/`：尚未纳入稳定工作流的短期实验。

## 协作入口

开始任务前先读 [AGENTS.md](AGENTS.md)，确认目录、语言、上下文和 Skill 路由规则。讨论 AI Native 方法或生产接口设计时，再读 [AI Native 游戏开发原则](AI_NATIVE_GAME_DEV_PRINCIPLES.md) 的相关章节；进入具体 UE 项目时，遵循该项目 Docs 入口选择任务所需的上下文和专项 Skill。

重要文档按职责维护：原则文档记录跨项目判断，项目文档记录当前项目事实，Planning 记录目标需求，ProgramWorkflow 记录任务交接与 Review，worklog 和决策索引记录历史。不要用历史记录替代当前项目事实，也不要默认通读所有文档或 Skills。
