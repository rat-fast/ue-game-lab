# UE 与 AI Native 游戏开发学习地图

## 文档用途

这份文档是当前学习计划的唯一事实来源，负责维护：

- 学习者画像、已有基础和交流颗粒度。
- 总体学习目标、各领域预期深度和模块顺序。
- 教学循环、总控线程与模块线程的组织方式。
- 当前项目、已完成阶段、下一步和学习路线调整。

这份文档不负责：

- 规定 Codex 的 UE 教学行为；该职责属于 `.codex/skills/ue-game-development-learning-companion/SKILL.md`。
- 规定 AI Native 工作流探索与设计方式；该职责属于 `.codex/skills/ai-native-design-collaborator/SKILL.md`。
- 详细论证 AI Native 的概念、架构和治理原则；该职责属于根目录的 `AI_NATIVE_GAME_DEV_PRINCIPLES.md`。
- 保存具体模块的完整课堂笔记、实现规格、代码说明和实验记录；这些内容应进入对应项目文档或独立专题文档。

它不是固定课表，也不是能力评级。模块顺序、学习深度和画像都应根据实际操作持续修订。

## 学习者画像

- 有商业游戏项目经验，当前主要岗位背景是数值策划。
- 熟悉数据表和配置工作，但不希望课程只围绕数值策划展开。
- 对完整游戏研发、其他策划方向、程序、美术、TA、动画、特效、音频、UI、QA 等领域缺少系统认识。
- 基本没有 Unreal Engine 实操经验，但接触过 Unity Visual Scripting，也具备基础代码概念。
- 已有一些商业研发中的隐性经验和风险直觉，但知识分布不均，部分概念停留在听过或模糊理解，未必经过实操验证。
- 希望建立全面知识地图，能听懂跨岗位讨论、理解产物与上下游、判断实现成本和风险。
- 学习不采用过度基础的“宝宝教学”，也不预设已经掌握商业策划应懂的概念；默认动态校准、能快则快、需要落地时再补基础。
- 当前以 C++ 作为 UE 稳定框架和运行实现的理解主线，同时系统学习阅读 Blueprint，理解传统项目如何在 C++、Blueprint、配置、资产和专用编辑器之间分配职责。
- 不再预设 Blueprint 应被整体删除或合并进 C++。学习时要识别它承载的配置、对象组装、资源绑定、业务编排和领域表达，并判断未来应保留、增加 AI 接口，还是由新的 AI 友好生产载体承接。
- 当前第一轮学习不急着引入 Lua、C# 或复杂自研脚本层；先理解 UE 原生对象、C++、Blueprint、配置、资源、工具与运行时状态之间的关系，遇到真实架构需求再扩展。
- 长期关注 AI Native 游戏生产，但现阶段先理解真实游戏开发，再判断哪些知识、流程和工具适合 AI 参与。

## 总体学习目标

学习完成第一轮后，期望能够：

1. 解释一个游戏功能从体验意图到运行时结果的完整链路。
2. 在 UE 项目中定位主要对象、配置、代码和资源。
3. 阅读主要 C++ 结构，完成小范围修改并运行验证。
4. 理解不同岗位的输入、输出、专业判断和协作边界。
5. 遇到不熟悉领域时，知道应该追问什么、查看什么、如何借助 AI 深入。
6. 从专业知识语义化、工具 AI 友好化、验证、上下文和治理角度观察研发流程。
7. 能分析一个玩法功能为什么被放在 C++、Blueprint、配置或专用工具中，并判断 AI 应操作哪个生产接口，而不是默认直接修改源码。

## 学习深度

| 层级 | 能力说明 |
|---|---|
| 认识 | 知道术语、用途、相关岗位和上下游。 |
| 理解 | 能解释对象关系、运行过程、主要状态和常见取舍。 |
| 实践 | 能在项目中定位、阅读、修改并验证。 |
| 设计与评审 | 能表达目标、比较方案、发现风险并审核 AI 或他人的结果。 |

默认深度：

- UE 核心与 Gameplay：达到“实践”。
- 配置、设计转换和 AI Native：逐渐达到“设计与评审”。
- 美术、动画、特效、音频、UI 等专业管线：至少达到“理解”，选择性实践。
- 引擎底层、网络、渲染算法等深层技术：先达到“认识/理解”，遇到真实问题再深入。

## 教学颗粒度与能力判定

- 面向 AI 辅助开发，不要求预先掌握下一层细节，但要知道下一层有哪些方向、何时需要追问 AI，以及应追问到什么层级。
- 先建立系统全景和对象关系，再进入局部执行链；不要用一串孤立 API、节点或代码代替整体理解。
- 内容分为主线、路标和深挖：主线当前理解，路标点明名称、职责和位置，深挖留到真实修改或排错时进行。
- 首次接触项目对象时，说明它属于代码、Blueprint、资产、类、运行时对象、Component、引擎系统、配置还是运行时状态；UE 中文界面字段同时给出中文和英文名称。
- 遇到 Blueprint 或专用图资产时，不只解释节点效果，还要说明它为什么位于这一制作层、由什么岗位维护、如何调用 C++ 能力，以及如果 AI Native 化应由什么接口承接。
- 代码优先按职责、环节和对象关系解释，再按需要进入具体语法和实现。
- 以当前项目的真实现象和约束为准；通用情况作为扩展路标，不用虚构例外干扰主线。
- 讲解对象或流程时，补充 AI 能否读取、修改或操作，以及需要什么接口、验证和人类确认。
- 每个模块结束前粗略展示未来可深挖的分支，并区分“第一轮浏览完成”“引导式实践完成”和“专业能力形成”。

## 学习地图

### 1. 游戏研发全景与设计基础

理解体验目标、系统设计、技术方案、资源生产、集成、测试、发布和运营之间的关系。

### 2. UE 项目与对象体系

理解 Project、Module、Level、World、Actor、Component、Asset、类、默认值和运行时实例。

### 3. Gameplay Framework

理解 GameMode、GameState、PlayerController、PlayerState、Pawn、Character 及其生命周期和职责边界。

### 4. 输入、移动、碰撞、导航与相机

理解玩家输入如何变成世界行为，并能阅读、调整和验证角色移动链路。

### 5. 交互、战斗、技能与状态

理解交互、攻击、伤害、生命、Buff、技能、事件和反馈如何形成完整 Gameplay 链路。

### 6. 敌人 AI 与生成管理

理解 AIController、感知、导航、StateTree/Behavior Tree、Spawner 和敌人运行状态。

### 7. 数据、配置、内容与存档

理解 DataTable、DataAsset、外部配置、运行时状态、SaveGame 和数据驱动内容生产。

### 8. 关卡与世界构建

理解空间设计、地形、导航、光照、关卡节奏、World Partition 和程序化内容的基本生产方式。

### 9. UI、音频与综合反馈

理解 HUD、菜单、信息层级、音效、镜头、震动及其与 Gameplay 状态的连接。

### 10. 美术、材质、渲染与技术美术管线

理解模型、纹理、材质、灯光、Shader、LOD、碰撞、DCC 和 UE 资产导入链路。

### 11. 动画、特效与角色表现

理解骨骼、蒙皮、动画状态、Montage、Root Motion、Niagara 和跨专业表现联调。

### 12. 工程化与 AI Native

理解 C++ Module、插件、版本管理、日志、调试、测试、性能、网络、构建发布，以及 AI Native 的长期生产方式。

AI Native 不只放在最后一课，而是贯穿所有模块，持续观察：

- 专业知识如何被准确语言化。
- 工具如何变得可查询、可调用、可回滚。
- 结果如何被观察、验证和评审。
- 项目上下文和决策如何积累与追溯。
- AI 如何在明确责任、权限和生产价值下参与工作。
- 传统生产入口承担了什么业务语义，以及 AI 友好化后由配置、领域模型、专用工具还是代码扩展承接。

这些内容在普通模块中只作为轻量观察和未来问题记录，不要求立即使用 AI Native 工作流设计原则，也不提前确定 schema、工具或自动化方案。需要深入设计时，转入独立的 AI Native 工作流讨论。

## 默认教学循环

```text
先体验实际现象
-> 建立最低必要概念
-> 在项目中定位对象
-> 追踪运行链
-> 做一个小范围改动
-> 运行并验证
-> 补充岗位与生产流程
-> 观察 AI Native 机会
```

教学时遵循：

- 不要求预先记忆大量 API 或节点。
- 先理解系统地图、职责、因果和验证方式，再按需深入底层。
- 用真实项目和运行结果校准模糊概念，不只讲抽象术语。
- 用户可以随时要求快进、放慢、向底层深入或返回生产视角。
- 进入自有功能改动后，优先建立适量日志和调试信息，作为人和 AI 共享的可观测接口。

## 对话组织

采用“总控线程 + 模块线程”的上下文分层方式。

### 总控线程

当前长期对话作为总控线程，主要讨论：

- 学习路线、学习画像和进度调整。
- 游戏研发的整体结构与跨模块关系。
- AI Native 原则、机会判断和工作流方向。
- 各模块学习结果的汇总、连接和复盘。

总控线程不持续展开具体 API、代码逐行讲解和编辑器操作。

### 模块线程

原则上每个大模块新建一个独立对话。模块较大时，可以按一个完整功能或产物继续拆分；不为了形式严格保持一模块一线程。

模块线程负责：

- 具体概念教学和问题校准。
- UE 编辑器操作、C++ 阅读与修改。
- 运行、日志、测试和验证。
- 该模块对应的岗位、产物和 AI Native 观察。

新模块线程应先读取：

1. `E:/agent/game/AGENTS.md`。
2. `E:/agent/game/.codex/skills/ue-game-development-learning-companion/SKILL.md`。
3. `E:/agent/game/docs/UE与AI Native游戏开发学习地图.md`。
4. 当前 UE 项目的相关本地文档和文件。

建议的新线程起始语句：

```text
请先完整读取并遵守：
E:/agent/game/AGENTS.md
E:/agent/game/.codex/skills/ue-game-development-learning-companion/SKILL.md
E:/agent/game/docs/UE与AI Native游戏开发学习地图.md

```

模块阶段结束时，应留下简短交接信息：已理解内容、完成的实践、仍不确定的问题、相关产物，以及学习地图中需要更新的进度。总控线程根据交接结果继续调整全局路线。
