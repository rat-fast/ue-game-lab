# 2026-08 工作记录

### 2026-08-03：形成 UE 与 AI Native 学习地图

- 内容：整理完整游戏研发学习路线、学习深度、教学循环、总控与模块对话组织方式，并记录当时的项目进度。
- 影响：后续学习能够按模块推进，同时把传统 UE 能力作为识别 AI Native 生产接口的现实基础。

### 2026-08-04：确立领域生产层与渐进式建设

- 内容：修正“取消 Blueprint、全部转为 C++”和“让 AI 默认直接修改源码”的早期设想，明确 Blueprint、配置、资产和专用编辑器还承担组装、资源连接、业务编排和领域表达职责。
- 影响：目标转为建立人和 AI 共用的领域语义与生产入口；工作流先通过真实任务试错，再根据重复证据逐步固化。

### 2026-08-04：划分项目文档和 Skill 职责

- 内容：整理项目文档、学习地图、通用原则和 Codex Skill 的职责边界，开始用项目入口、整体架构和模块文档组织 AI 上下文。
- 影响：项目事实逐步回到项目本地文档，避免所有知识都堆进根目录规则或对话历史。

### 2026-08-06：学习数据、配置与内容生产

- 内容：围绕 DataTable、DataAsset、外部配置、运行时状态和 SaveGame 梳理数据链，开始区分参数配置、内容生产和运行状态。
- 影响：为后续讨论技能的数据驱动层级提供了 UE 实际对象基础。

### 2026-08-08：扩展到关卡、UI、音频与综合反馈

- 内容：进入 Level、World、导航、光照、HUD、Widget、Gameplay 状态、音频和镜头反馈的第一轮学习。
- 影响：开始从完整可玩体验理解 Gameplay 逻辑与表现、世界和反馈系统的连接，而不是只关注技能逻辑。

### 2026-08-09：学习美术、材质与渲染管线

- 内容：梳理模型、纹理、材质、灯光、镜头和技术美术管线，以及这些资源怎样进入 UE 并参与运行效果。
- 影响：确认技能和角色表现依赖真实资源生产与绑定，AI 生产流程不能只覆盖代码和配置。

### 2026-08-09：调研 UE MCP 接入方式

- 内容：调查 UE 5.8 的 `ModelContextProtocol`、`AllToolsets` 和 Codex 连接方式，并建立端口配置入口。
- 影响：明确 MCP 能提供编辑器操作入口，但“能够调用工具”不等于已经具备高效、稳定的领域生产能力。

### 2026-08-09 至 2026-08-24：完成敌人近战链路实验

- 内容：围绕独立测试关卡、敌人 Blueprint、AIController、StateTree、攻击动画、生命组件和伤害链路进行实际勘察与实施。
- 影响：获得一个跨 AI、动画、伤害、组件和关卡的真实样本，也暴露出通过 MCP 逐节点修改 Blueprint 效率较低的问题。

### 2026-08-25：建立 SkillLab 主控方向

- 内容：决定新建独立的技能领域实验项目，不再把目标设为先做完整游戏；主控对话负责范围和进度，具体学习与实施任务拆到独立对话。
- 影响：研发主线收束为验证 AI 能否深度参与复杂技能生产，以及哪些 UE 生产对象需要改造接口。

### 2026-08-25：深入比较代码、配置、DSL 与底层原语

- 内容：讨论数据驱动的不同深度，从参数配置、行为组合推进到可执行配置、技能 DSL 和中间表示；同时指出把 Blueprint 节点机械搬进 JSON 只会得到“文本版 Blueprint”。
- 影响：有限技能 DSL 被保留为候选，但不再预设它必然优于 C++ 或 Blueprint；是否建设要由重复生产、校验和 AI 效率收益证明。

### 2026-08-26：确定先做生产接口审计

- 内容：调整原先“先确定 C++、JSON 和 Blueprint 分层”的顺序，决定先选代表性技能，观察 AI 对代码、配置、Blueprint、GAS 资产、动画、Niagara 和运行结果的读取、修改与验证能力。
- 影响：工具改造将针对真实瓶颈进行，不再事前建设一套未经验证的完整技能平台。

### 2026-08-27：把 AI 目标提升为技能生产者

- 内容：明确目标不是让 AI 代替策划填写配置，而是逐步承担技能意图理解、机制设计、实现、表现接入、运行验证和迭代。
- 影响：配置被重新定位为生产接口之一，而不是项目目标；SkillLab 第一阶段至少应研究从局部助手向完整生产者推进的条件。

### 2026-08-27：启动 GAS 独立学习

- 内容：建立独立对话学习 `AbilitySystemComponent`、`GameplayAbility`、`GameplayEffect`、`AttributeSet`、`GameplayTag`、`GameplayCue` 和 Ability Task，并比较不同岗位需要理解的深度。
- 影响：形成“GAS 是成熟 Gameplay 运行后端候选，但不是技能设计方法，也不是 AI Native 的必要条件”的判断；暂不因学习 GAS 就直接绑定 SkillLab 架构。

### 2026-08-29：把受限脚本层纳入候选

- 内容：讨论在 C++/GAS 与配置之间增加脚本层，用于表达复杂、变化频繁的条件、循环、状态、事件和动态计算。
- 影响：脚本被视为可能的安全业务逻辑层，但由于运行时、沙箱、调试、版本和性能成本，决定先等待真实瓶颈再做小型实验。

### 2026-08-29：准备 SkillLab 的 UE 工具接入

- 内容：SkillLab 项目启用 `ModelContextProtocol` 和 `AllToolsets`，并保留为独立的 Blank C++ 实验项目。
- 影响：项目具备后续通过 UE 工具进行场景、资产和运行验证的基础，但技能后端和数据格式仍未锁定。
